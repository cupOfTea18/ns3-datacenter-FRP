时延扫描保留程序按时延自动计算 headroom 的规则，因此各时延下的 headroom 不相同。它还改变在途量、探测周期和 RTT/窗口；图 6 是“现有配置规则随传播时延变化”的敏感性，不能解释为所有其他物理资源固定的纯控制时延实验。每个时延点内的算法使用相同公共资源。

## 4. 图 3：逐流反应、预算与实际发送

![图 3：逐流控制链](../results/r3-paper-20261008/figures/fig03-flow-reaction.png)

[PDF](../results/r3-paper-20261008/figures/fig03-flow-reaction.pdf)。使用 ECN off、history、seed 1；实线有竞争，虚线无竞争。30 ms 竖线表示 F3 开始。B wire TX 与接收端 payload goodput 均汇总到固定 1 ms 桶，两种速率口径不能混用。

30–80 ms 内，F1 的 B 降速计数增加 18，反应上限最低约 52.960 Gb/s；F2 没有 B 降速，反应上限为 100 Gb/s。**但两流预算在这一窗口始终为 49 Gb/s。**因为 F1 降速后的上限仍高于端口等分份额，B 的逐流反应尚未改变该窗口的预算。右上图曲线重合是实际数据，不是缺线。

因此图 3 支持“反馈/反应状态有差异”，不能独立支持“B 已对拥塞流实施更低预算”，也不能把 F1/F2 实际发送差异全部归因于 B。RNIC、A 的组限额、下游排队等仍在共同作用。这是当前论文 C1 的重要补证缺口。

## 5. 图 4：队列预测误差和服务模型诊断

![图 4：精确时间终点的队列对照](../results/r3-paper-20261008/figures/fig04-prediction.png)

[PDF](../results/r3-paper-20261008/figures/fig04-prediction.pdf)，[逐点数据](../results/r3-paper-20261008/figures/prediction-replay.csv)，[误差指标](../results/r3-paper-20261008/figures/prediction-metrics.json)。使用同一条 ECN off/history/seed 1 轨迹，比较：

1. 在线时间桶重建；
2. 离线逐包到达输入、保持相同常值服务估计的重放；
3. 旧快照队列作为估计；
4. 动作到达时刻的事件级 B 队列；
5. 使用未来实际 B 出队的离线守恒 oracle。

第 3 项是**同一 history 轨迹上的估计器比较**，不是另一次 snapshot 闭环运行；后者的 FCT 对比在图 5。oracle 使用未来信息，只用于核对守恒，不能作为可在线部署的方法；它与实际队列重合部分来自构造关系，不是独立的预测准确性证明。

### 时间和事件顺序如何核验

A→B 是当前拓扑中的直接 DCI 链路；每个受控数据包均为 1,048 B。由逐包 A 出队时间加传播、序列化、B 接收处理时间得到到达事件。本次固定总延迟为 5,015,041 ns。结合实际 B 出队事件，重建组队列。

对前 120 ms 内全部 2,400 个 B 采样时刻核对输入/输出累计计数：无一落在对应包事件的前后计数范围之外。同纳秒碰撞涉及 6 个到达采样、8 个出队采样，前后最多相差 1,048 B。这来自仿真事件先后顺序，不能简单全部使用时间戳 `≤t` 或 `<t`。

本图从快照的实际计数开始，保留快照边界；终点采用“该纳秒所有包事件执行后”的明确口径。没有插值相邻的 50 μs 队列样本，也没有把同纳秒差异当作任意可容忍误差。

### 定量结果

| 估计器 | 30–80 ms MAE | 仅 A 有积压样本的 MAE |
|---|---:|---:|
| 在线 history | 733,541 B | 2,186,063 B |
| 逐包输入 + 原常值服务 | 734,281 B | 2,188,119 B |
| 同轨迹旧快照 | 6,518 B | 15,317 B |

全窗口为 1,000 个样本，其中 A 有积压为 239 个。逐包输入重放与在线重建误差接近，说明在本轨迹上，时间桶近似不是百万字节级误差的主要解释；常值服务外推仍是应优先调查的模型项。

最大在线预测出现在 43.7 ms：预测 28,447,949.56 B，终点为 48.715041 ms；**该终点事件级真实队列为 20,960 B**，不是历史邻近 48.75 ms 样本的 0 B。修正时间对齐后，过度预测的结论仍成立，但论文应区分这两个数值。

此时服务估计为 49 Gb/s，而从快照至精确终点的实际平均出队约为 71.594 Gb/s。实际出队也受供给限制，不等于真实可用服务容量；不能因此直接用该平均值设计在线服务模型。图中无积压阶段的大服务估计也不能简单归为错误，因为空队列时能力与实际出队并不相等。

## 6. 图 5：配对消融与性能权衡

![图 5：配对消融](../results/r3-paper-20261008/figures/fig05-ablation.png)

[PDF](../results/r3-paper-20261008/figures/fig05-ablation.pdf)。柱为 3 seeds 均值，散点为所有 seed 的值。下表为 FCT 均值，单位 ms；完整逐 seed 数据见[指标 CSV](../results/r3-paper-20261008/figures/experiment-metrics.csv)。

| 配置，5 ms | F1：0→41 | F2：0→59 | F3：42→41 |
|---|---:|---:|---:|
| DCQCN | 149.107 | 119.223 | 91.862 |
| ECN on / history | 631.508 | 590.997 | 51.682 |
| ECN on / snapshot | 698.396 | 698.439 | 46.772 |
| ECN off / history | 255.570 | 216.472 | 65.415 |
| ECN off / snapshot | 233.205 | 217.728 | 65.471 |

候选 ECN 相比默认 R3 改善跨域完成时间，但让本地流变慢。相对 DCQCN，候选 R3 仍是跨域流慢、本地流快，不能写成全局性能改善。默认 ECN 配置存在很大的 seed 间波动；在仅 3 seeds 的条件下，不宜用均值排名宣称可靠优势。

history 对受竞争流 F1 的候选均值比 snapshot 更差，对 F2 则略好；这是不一致的收益。没有删掉退化样本，也没有只统计完成更快的一条流。

下排指标口径：

- 队列峰值是同一 B 向内出口/PG 的公共 100 μs 采样峰值，对各算法口径相同，不是逐包真实峰值，也不是全网最大队列。
- PFC 是 `pfc.csv` 的**事件记录数**，包含 trace 所记录的发送/接收/恢复等事件，不能等同于唯一暂停报文数或暂停时长。
- 控制开销为两网关在 `[10 ms, 本次最后一流完成]` 内发送的 STATE/DEMAND 字节，除以 A 发出的跨域数据 wire 字节。不计完成后持续的周期报告，也不包含全部 ACK/CNP/PFC。DCQCN 的 0 仅表示无 R3 STATE/DEMAND 开销。

**10 ms 点的机制验收限制：**六次 R3 运行均通过完成/字节/资源验收，路径关系也正确，但 30 ms 后共同供给仅维持约 53.816–54.515 ms，低于公共分析要求的 `max(20 ms, 3×base RTT)=60.684 ms`，所以 `scenario_relation_status=fail`。三个 DCQCN 运行通过该项。图中保留所有有限流 FCT 点并显式标注，不能用该点比较持续竞争的收敛/公平性，或声称已在长时延下完整验证机制。若后续要研究该问题，应为所有时延和算法统一制定更长竞争业务的新矩阵，不能只延长对 R3 有利的个别运行。

图 6 只覆盖传播时延，不宣称已经完成负载、并发流数、incast、多 PG 或多网关扩展性验证。这些需要不同的流量合同和基线验收，不能将当前 3 流场景重复运行冒充规模实验。

## 8. 图 7：无竞争对照揭示反馈语义问题

![图 7：反馈与无竞争对照](../results/r3-paper-20261008/figures/fig07-feedback-control.png)

[PDF](../results/r3-paper-20261008/figures/fig07-feedback-control.pdf)。seed 1，history；红色默认 ECN，蓝色候选 ECN；实线有 F3，虚线无 F3。

即使没有本地竞争流，默认 ECN 仍出现大量 B 降速事件，两条跨域流 FCT 为 1,046.655/1,048.833 ms；候选对照为 173.719/173.720 ms。这个结果说明默认反馈不能直接被当成指定接收端竞争的指示信号。它支持进一步调查整形队列反馈与串联控制的作用，但没有证明所有拥塞来源已被分离。

“降速事件计数”记录算法分支执行，包含在下限处重复执行的可能，不能当成每次都带来实际速率下降。候选曲线在左图接近零并非缺失，与默认配置的事件数量级不同。

## 9. 验收与复现

本轮 35/35 次运行完整性通过，103/103 条流完成。所有逐流发送/接收 payload 闭合，无 payload 重传；全网准入丢弃和停止残留为零。R3 运行还检查了两条跨域流的 A 入/出、B 入/出 wire 字节一致、逻辑队列最终为零，快照拒绝计数为零。DCQCN 没有 R3 专属 wire 日志，不把未记录的网关字段当作已经通过。

5 ms 核心场景的公共分析结果为 15 项机制关系通过、2 项无竞争对照关系不适用；1 ms 为 9 项通过；10 ms 为 3 项通过、6 项共同供给窗口不足而失败（详见图 6）。所有路径关系均正确。机制路径、供给重叠和性能统计需要分别解读，不能把 exit 0 当作收敛保证。

## 10. 对论文主张的修订建议

当前可直接写入论文的是：真实层次路径、可执行控制链、配对消融、明确的时间对齐，以及“已知输入更准确但服务模型仍会使预测失败”的实证发现。

需要继续验证的核心机制有两项：其一，设计使逐流反应上限真正约束预算、同时保留可比供给的场景，再比较统一组级反应；其二，在同一轨迹上分析服务组成变化，提出最小可在线估计后重新做 history/snapshot 对照。本轮没有为了得到好看的图修改控制算法或调参。

新增的精确终点分析比历史邻近采样更可靠，但它并没有挽救现有预测收益主张。论文应保留这组反例，并把“提升性能”的候选贡献与“揭示失效条件”的已观测结果分开。
