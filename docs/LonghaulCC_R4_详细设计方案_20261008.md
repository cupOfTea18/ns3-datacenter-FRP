## 1. 已确认的设计边界

1. 取消 R3 独立控制组，控制对象为流，资源协调对象为物理出口端口。
2. 第一阶段优先验证机制，允许 A/B 维护逐流状态、逻辑队列、预算、整形和发送历史；记录成本，暂不要求硬件线速实现。
3. 主机保留 DCQCN、原有可靠传输和原生反馈行为，主要修改 A/B 网关。
4. 对 R4 注册跨域流，A 建立 ECN 反馈边界：源侧 CE 由 A 消费并转成近端 CNP，向 WAN 转发前清除；A/B 受控整形出口不产生新 CE。B 保留已有 CE，观察边界之后的拥塞反馈；下游普通交换机继续标记。原生 CNP/ACK-CNP 继续返回主机；A 不因同一原生反馈再次执行乘法降速。
5. PG 用于底层分类、缓冲和 PFC，不再作为 R4 控制分组键。R4 必须感知流是否可发送以及暂停造成的实际服务变化。
6. 保留真实路径：源主机→Leaf→Spine→A→WAN→B→Spine→Leaf→接收主机。
7. 首版范围为现有单对网关、固定路由、固定连接注册和仿真同步时钟。多源网关、路由迁移、真实时钟同步不纳入首版结论。

研究目标：在共享端口约束下保留逐流反应差异，减少聚合排空造成的额外限速，并验证实际发送历史能否改善反馈延迟下的注入决策。分流不保证吞吐隔离；PFC、物理带宽、共享缓冲和主机 DCQCN 仍可造成流间影响。

## 2. 从 R3 改什么

本节保留最初从 R3 迁移的设计背景，当时源码依据为 `DciGatewayNode`、`longhaul-r3.h`、`QbbNetDevice` 和 `BEgressQueue`；不是当前实现状态清单。R3 已有逐流逻辑队列、入队/出队计数、B 反应状态和逐流整形；历史、快照队列、服务估计和 A 排空上限仍按组维护。

| 内容 | R3 | R4 |
|---|---|---|
| 控制标识 | 流与控制组 | 流及其连接代次 |
| B 队列与服务报告 | 组队列、组服务、逐流预算 | 每流队列、预算、服务观测和执行状态 |
| A 实际发送历史 | 每组 | 每流 |
| A 排空 | 组限额，再分配给流 | 每流注入上限 |
| A 端口分配 | 先组间、后组内 | 同端口所有活动流联合分配 |
| B 端口分配 | 跨 PG 联合分配 | 保留，以发送资格和逐流上限为输入 |
| 控制消息 | 组快照原子应用 | 独立完整的逐流记录，可批量装包 |
| 共享缓冲保护 | 网关总量保护 | 保留为应急保护，区别于常规逐流控制 |

不将 R3 每个组改成单流组作为最终结构；删除组状态和两级分配依赖。批量消息、端口流列表只是实现索引，不拥有独立控制限额。

现有 [R3 实验与结果文档](LonghaulCC_R3_论文实验与结果图_20261008.md) 提示：反应上限不同不一定使预算不同，常值服务外推可能产生明显误差。这是已有文档记录，本轮没有重新核查原始轨迹；不能作为 R4 的实验结论。

## 3. 控制分工与状态

| 位置 | 输入 | 输出 |
|---|---|---|
| B 逐流反应 | 原生反馈、近期到达、实际发送 | 反应上限 r_i |
| B 端口分配 | 各流上限、需求、发送资格、端口资源 | 转发预算 b_i |
| B 逐流观测 | 实际队列、出队、积压时间、暂停 | STATE 记录 |
| A 逐流预测 | STATE、实际发送历史 H_i、前向时延 d_i | 预测队列 qhat_i |
| A 逐流控制 | 队列估计、服务估计、预算、目标队列 | 候选注入上限 v_i |
| A 端口分配 | 所有流的 v_i、实际需求、发送资格 | 实际整形目标 u_i |

### 3.1 逐流状态

- 身份：flow_id、generation、peer、数据/反馈匹配键、A/B 出口映射。
- 生命周期：未启动、活动、空闲、排空、完成；暂停和反馈失效为正交标志。
- B：反应上限、反馈平滑量、预算、累计成功入队/实际出队字节、队列字节、最近到达和反馈时间、服务观测窗口、需求报告时刻。
- A：实际发送时间桶、最近完整 STATE、报告有效性、预测队列、候选限额、执行目标、探测剩余额度、近源反馈时间。
- 底层发送资格：由 PG/PFC、设备和队列状态得出；R4 使用该结果，不按 PG 分配控制份额。

每个控制记录采用独立递增序号和采样时间。身份与 generation 分开校验；数据匹配歧义必须拒绝，不静默把不同连接合并。首版沿用预注册身份，不宣称动态硬件流表已经解决。

### 3.2 端口状态

保存物理容量、活动流列表、非受控实际发送计数、可分配容量估计、总目标队列、探测令牌和共享保护状态。每个控制周期只对同一个端口计算一次资源预算。

统一单位：内部速率 byte/s、队列和发送量为 wire byte、时间为 ns 或明确的秒值；日志 `_bps` 表示 bit/s。payload goodput 另行统计，不与 wire 速率混算。

## 4. B：反应、分配与观测

### 4.1 逐流反应上限

首版承接 R3 的窗口合并反馈规则，以减少同时更换多个机制：

\[
\alpha_i\leftarrow(1-\gamma)\alpha_i+\gamma e_i,
\qquad r_i\leftarrow\max(r_{probe},r_i(1-\alpha_i/2))\quad(e_i=1).
\]

同一反应窗口多个反馈只触发一次反应。没有反馈不直接等于可增速；只有近期有到达、实际发送增长、未暂停且恢复等待完成时，才执行有界加性恢复。上限不超过 B 出口物理容量。反应上限始终区别于预算与实际出队速率。

活动需求由 B 实际积压、近期到达和有效 A DEMAND 共同判断。B 空队列不能单独判为无需求。暂停流仍保留需求状态，但暂不参与正速率分配。

### 4.2 端口容量与预算

首版沿用剩余容量估计：

\[
\widehat C_p^B=\left[\rho C_p^B-D_{other,p}/\Delta_c\right]^+.
\]

`D_other` 包含实际占用该出口的非受控数据和控制报文，按相同字节口径计量。它是上一周期观测，不保证下一周期的剩余容量。正常与乐观启动模式每流上限 c_i 为 r_i；保守探测/重新活动探测时再施加探测速率约束。无有效需求或不可发送时 c_i=0。

\[
b_i=\min(c_i,\lambda_p),\qquad
\sum_{i\in p}b_i\le\widehat C_p^B.
\]

采用带上限等权最大最小分配，剩余容量在未达到上限的活动流之间重分配。通过逐流令牌桶执行 b_i；不改变主机 DCQCN。调度器必须跳过空队列、暂停队列和令牌不足队列，避免一个流阻塞其他可发送流。

### 4.3 首版逐流服务模型

服务估计是待验证的模型，不是预算保证。为避免引入过多参数，首版使用一个固定长度观测窗口 W_s，不再叠加多级平滑。

记录窗口内：实际出队字节 D_i、有积压墙钟时长 T_i^busy、暂停时长和当前预算 b_i。有积压时间包含因暂停、令牌不足或调度竞争而等待的时间。按事件更新队列从空到非空、从非空到空的边界；出队事件只计一次，明确同时间戳事件先后次序。

定义候选有效服务估计：

\[
\widehat s_i=
\begin{cases}
0,&\text{当前执行受暂停阻塞},\\
\min(b_i,D_i/T_i^{busy}),&T_i^{busy}\ge T_{min},\\
b_i,&\text{观测不足且未暂停}.
\end{cases}
\]

第三种情况标记 `budget_fallback`，不是测得的服务能力。首版建议 W_s 为一个报告周期、T_min 为一个控制周期；均写入有效配置，不把这个初值当成性能最优参数。若报告时处于预算变化后的过渡期，记录预算变化时间，供误差分层分析；首版不猜测其他流未来的行为。

该估计减少“空闲时间把吞吐拉低”的直接混淆，但仍受短窗口、包粒度、历史暂停、令牌突发及预算变化影响。采样后恢复或竞争变化仍不可知。需要比较预算服务模型与此观测模型；若观测模型更差，不能仅凭其测量来源而保留。

### 4.4 逐流目标队列

禁止为每条流复制固定的大队列目标。B 配置每出口总目标 Q_p^*，按该周期正预算比例分配：

\[
q_i^*=Q_p^*\frac{b_i}{\sum_{j\in p}b_j}.
\]

分母为零时全部目标为零；发送预算为零的流不获得新的目标份额。目标允许小于一个包，不设置会随流数膨胀的每流最小字节数。报告携带本次 q_i^*，A 不自行根据不同龄期记录重算 B 的分配。

配置检查要求所有端口目标之和小于指定受控缓冲预算，并留出明确安全余量；目标不是缓冲预留，更不是无损证明。流数变化会改变目标，必须测试其瞬态影响。

## 5. A：历史重建、注入与端口协调

### 5.1 实际发送历史

H_i 只记录 A 真实数据出队进入 WAN 的事件，不记录目标速率、A 入队量或主机发送意图。暂停、无供给和令牌不足造成的少发自然体现在历史中。

报告采样为 t_s，A 决策为 t，固定前向延迟为 d_i，预测终点为 t_a=t+d_i。回放的源发送区间为 [t_s-d_i,t]，映射为 B 到达区间 [t_s,t_a]。首版按固定包大小和已核验时延路径实现；包大小变化时需按序列化时延重新定义映射。

\[
\widehat q_{i,k+1}=\max(0,\widehat q_{i,k}+D^{actual}_{i,k}-\widehat s_i\Delta_k),
\quad \widehat q_{i,0}=q_i(t_s).
\]

边界桶均匀分摊是近似，明确记录桶宽。历史保留窗口至少覆盖最大允许报告年龄加前向时延并留边界桶余量；启动前负时间按零发送处理。缺历史不得伪装为全零输入。

### 5.2 首版候选注入控制律

在报告有效、历史完整且本流有发送需求时：

\[
v_i=\min\left\{b_i,\left[\widehat s_i-
\frac{[q_i^{used}-q_i^*]^+}{\tau}\right]^+\right\}.
\]

历史版使用 q_i^used=qhat_i；旧快照版使用 q_i^used=q_i(t_s)。两者使用相同预算、服务模型、端口分配和异常处理。

首版只在积压超过目标时扣除排空速率，不因低于目标而无限提高注入。tau 是控制强度参数，不宣称等于收敛时间。用测得的低服务限制输入可能导致过度保守，必须通过恢复规则和消融检查。

### 5.3 A 端口分配

对同出口所有仍有有效需求、候选许可有效且底层可发送的流，直接执行；瞬时队列为空不取消资格：

\[
u_i=\min(v_i,\lambda_p^A),\qquad
\sum_{i\in p}u_i\le\widehat C_p^A.
\]

A 的容量估计与 B 使用相同口径，但观测各自端口。没有数据可发不等于不允许发送：活动流空队列时保留本周期合法整形目标和有界令牌状态，不因空队列将速率清零。新包到达后立即按已有许可参与设备调度，仍受令牌、物理端口和 PFC 约束，不等下一个控制周期重新开门。设备跳过空队列，不产生虚假 TX；需求结束、暂停、报告失效或控制律要求排空时仍可撤销许可。保留许可可能暂时占用分配份额，不能据此宣称已经实现空闲份额的即时借用。

乐观启动候选值按第 6.3 节计算；保守启动与恢复探测先计算单独受限的探测候选值，再与常规流共同接受最终端口分配。任何路径都不能绕过物理容量约束。

## 6. 启动、暂停、失效与结束

| 条件 | A 行为 | B 行为 |
|---|---|---|
| 新流、尚无有效活动预算（包括启动前零预算 STATE） | 发送 DEMAND，进入明确的启动策略，不因曾收到任意 STATE 而跳过启动 | 根据有效需求生成活动预算/STATE，不等待先收到数据；初始化策略见第 6.3 节 |
| STATE 有效、历史完整 | 正常逐流计算与端口分配 | 反应、分配、观测和报告 |
| 本地暂停 | 目标执行为零，继续控制消息与状态维护 | 同理；STATE 报告实际发送资格 |
| 收到远端暂停状态 | 正常数据候选为零，等待恢复报告 | 恢复后即使无数据也重算预算并限频报告 |
| 旧报告有效但服务为零、当前已可发送 | 有需求时允许有限恢复探测，不把正常限额自动恢复到满预算 | 收到探测后更新服务观测 |
| 报告过期或历史缺失 | 普通数据限额设零，继续 DEMAND；用新完整状态恢复 | 继续周期报告；过期需求不被当作持续无限需求 |
| 完成通知到达 | 停止新探测，保留历史与身份直到队列排空和尾部核对完成 | 有积压继续排空，不因 CLOSED 丢弃队列 |

### 6.1 保守探测与恢复的硬约束

以下是 `PROPOSED_STARTUP_MODE=probe` 保守启动及恢复探测路径的约束。默认 optimistic 启动按第 6.3 节执行，不使用这些启动字节额度；恢复探测仍遵守本节。

- 每流每次启动最多发送 P_probe 字节，P_probe 至少容纳一帧；不能因超时无限重置这个额度。
- 所有启动/恢复探测共享端口令牌桶，速率为 eta_probe*C_p、突发为 P_probe,p；并接受第 5.3 节最终容量分配。令牌按实际出队扣除，不按授予目标扣除。
- 恢复探测仅在新鲜 STATE 明确表示远端可发送且 b_i>0 时允许，候选速率不超过 b_i 和 r_probe。因积压超目标而被正常控制律压到零时，不启用恢复探测绕过排空。
- 针对低服务导致的零速率，只有报告队列不高于目标才可探测；若远端有积压，则让 B 先实际排空并更新服务报告。
- 一次恢复探测耗尽后，只有更新的报告证明 B 累计成功接收量增加，才刷新下一次额度。长期没有确认的数据不会反复投放；仍发送 DEMAND/STATE。
- 未获得反馈而停发是有意的保守行为，不承诺控制报文永久丢失时仍有进展。明确测试反馈恢复后的自动恢复。

STATE 的累计接收量只表示进入 B，不是到达最终接收机，不替代 RDMA ACK。探测字节、重传字节和正常数据都占真实端口资源并进入历史。

### 6.2 主机反馈与共享缓存保护

主机继续处理原生反馈。A 观察远端原生 CNP 仅用于记录和近源反馈限频，不执行额外乘法反应。近端 CNP 不经过 B，不进入 B 的反应状态。

对匹配注册身份、Source 角色和对应 WAN 出口的跨域数据包，执行以下规则：

1. 在 A 接收数据、尚未清除 ECN 字段时，观察已有 CE，按流记录源侧拥塞待反馈状态。
2. 近端 CNP 合并上游 CE 与 A 队列超过高水位两个触发来源，使用同一逐流限频机制。CE 即使出现于 A 空队列或低水位时也能置待反馈；当前 pending 只在实际近端 CNP 发出后消费，原生反馈抑制、限频或队列变空均不消费 pending。
3. A 记录源侧 CE 后、向 WAN 转发前立即改为 ECT(0)，无需等待近端 CNP 发出；保留 DSCP，不声称恢复已无法从 CE 判断的原 ECT 值。非 CE 包保持原 ECN 字段，Not-ECT 不自动改为 ECT。包头和缓存解析字段保持一致。
4. A/B 受控整形出口都禁止新增 CE；B 不清除已有 CE。下游普通交换机和非受控流保持 ECN 行为。双向流按各自 Source 角色确定边界，不能按固定节点编号处理。

A 高低水位仍按端口总阈值在有需求流间等分；先不同时调整水位、CNP 间隔和主机恢复参数。上游交换机仍通过 CE 报告真实拥塞，A 将其转换为本地反馈而不是无条件抹除。同一个包的 CE 重写不是重复计数问题，修订解决的是同一源侧积压同时驱动主机与 B 降速的问题。

该边界按流角色/出口划分，不是按物理排队原因精确分类：A 的受控流即使因真实出口竞争排队，也由近端反馈、端口分配及现有 PFC 处理。B 自身受控积压由 STATE、A 注入控制与端口协调处理，下游保留 ECN；B 仍不能定位远端域内具体拥塞点，主机和 B 对远端反馈的串联反应也仍存在。

正常模式必须同时启用 CE 转近端反馈、清除源侧 CE、禁止 A/B 受控出口新增标记；不能静默使用“清除但不反馈”。消融须显式标明偏离项。旧 `PROPOSED_SHAPER_ECN=0` 只屏蔽新增标记，不提供 A 消费/清除源侧 CE 的边界，因此不能单独替代本方案；它仍只允许用于显式 path 模式。

A/B 继续保留共享缓冲高低水位应急保护。触发时允许降低同一资源池内多流的可分配容量，并记录原因；这类共同影响不计为逐流隔离失败，但频繁触发意味着正常控制尚未充分有效，不能隐去相关样本。

### 6.2.1 B 积压与下游拥塞的处理边界（本轮修订）

B 因整形而积压时，降低 B 自己的服务预算会进一步减慢排空，形成“积压→自身 ECN→降预算→更多积压”的循环。因此禁止 B 受控整形出口新标记；不新增另一种反馈协议，也不清除 B 收到的已有 CE。

B 继续报告实际 q、b、s 和发送资格。A 根据第 5.2 节预算/预测队列排空项降低输入，B 按当前合法预算继续服务；B 预算仍受下游原生反馈、PFC、端口竞争和现有应急缓冲保护约束。这里没有保证 B 永不降速，而是去掉 B 整形积压作为自身原生反馈的来源。

实现按注册流与出口识别，不是将物理排队原因精确分离。同一 B 出口的非受控流仍可标记；受控流的出口竞争由端口协调及 STATE 处理，下游普通物理瓶颈继续 ECN。A 清 CE 与 B 保留 CE 的职责不同，禁止把 A 的 CE 改写应用到 B。

本轮只改变 B 受控出口的新标记策略；启动、利用率 0.98、主机恢复、水位和控制参数保持不变。元数据增加 `ecn_policy_revision=2`，并明确 `source_shaper_ecn=false`、`receiver_shaper_ecn=false`；修订前 source-boundary 曾保留 B 标记，历史结果不可混用。验收包括真实出队不新标记、已有 CE 保留、下游反馈仍引起 B 反应、M0 收发闭合，以及多流/下游竞争下的队列和丢弃检查。

本轮复测发现的实现缺口：`RdmaHw::ReceiveUdp` 当前把任意非零 ECN 都当作拥塞，ECT(0) 会被误报为 ACK-CNP。B 新标记关闭后 M0 已完成，但多流中 A 清 CE 的完整隔离尚不成立。需要另行确认并修正接收端为仅 CE 触发反馈；本轮尚未修改该主机文件，不能将此次通过解释为全部 ECN 语义已正确。

### 6.3 已确认的乐观启动策略

本轮用户明确选择：启动不设额外字节额度，先按端口容量发送，反馈到达后调整，并验证多流启动积压风险。配置 `PROPOSED_STARTUP_MODE=optimistic`；保留 `probe` 作为保守对照。

- A 首次活动且尚无有效活动 STATE 时，候选速率为 `min(A 出口物理容量, 已注册 B 出口物理容量)`，接受 A 端口联合分配及现有缓冲保护。不使用每流探测额度或共享探测桶；普通整形桶仍只有有限突发。
- B 首次进入活动状态时，以本出口物理容量初始化反应上限，并对所有有需求流按端口可用容量分配。M0 的初始候选为 100 Gb/s，B 单流预算受 utilization=0.98 约束为 98 Gb/s；多流不能各自独占全端口预算。
- 有效活动 STATE 是通过身份/序号/计数等校验、采样时间不早于本流 start 且带 HAS_DEMAND 的记录；不要求预算大于零。收到后永久记录已完成启动接管，后续使用正常控制。启动前零预算或无活动需求的报告不完成接管。
- 新鲜报告明确不可发送时立即遵守，不能被乐观启动绕过。无活动反馈持续到 `start + STATE_TIMEOUT` 时停发并继续控制消息；旧的非活动报告不延长这个期限。此处沿用反馈失效时间约束，没有新增字节额度。
- 正常运行后的报告失效不会重新获得乐观启动。B 首次活动以后的空闲重启保留原保守恢复规则，不再从线速初始化。暂停、预测排空和有限恢复探测规则继续有效。

远端出口容量不是下游整条路径的可用容量，活动预算也不是容量预留。反馈返回前多流可能形成明显积压甚至触发丢弃，必须报告真实 TX/RX、队列、PFC 与准入丢弃，不能把“未设额度”解释为无损保证。

## 7. 控制协议与一致性

R4 使用显式版本 4；不接受版本 3 记录。协议仍经实际网络传输，控制字节、时延、丢失和队列占用均纳入测量。

### 7.1 STATE：B→A

每条完整记录包含：flow_id、generation、seq、sample_time、q_i、b_i、s_i、q_i^*、累计成功入队字节、累计实际出队字节、活动/排空/完成标志、sendable、服务估计来源及观测窗口信息。观测窗口信息至少包含窗口长度、busy 时长和实际出队量，便于核验估计。

### 7.2 DEMAND：A→B

每条记录包含：flow_id、generation、seq、sample_time、本地积压、是否仍有需求、是否已收到完成通知、累计实际 WAN 发送字节。需求不是未来精确发送率；首版不依赖读取其他节点未来事件或内部队列。

### 7.3 打包与应用

- 同一采样轮可批量封装多条完整记录，每个报文不超过配置 MTU；一条记录不跨包。
- 每条记录独立应用，丢失一个包不会阻止其他流更新；不要求收齐整个端口的记录。
- 校验来源、目标身份、版本、generation、时间、序号、字段范围和累计计数单调性；拒绝旧记录和重复记录。
- 全部记录来自合法端口分配，但不同龄期的 b_i 合计可能超过 B 当前容量；首版承认这一暂态，不把旧预算称为预留。A 的本端分配无法保证消除远端超额，必须在竞争变化场景中测量。
- 状态超时按采样时间计算，不按接收时间重新续期。周期报告不因数据限额为零停止。
- 预算、暂停、完成变化可触发限频提前报告；周期报告提供最终刷新。不得每包发送完整控制快照。

## 8. 配置与实现范围

### 8.1 参数约束

保留反应、报告、控制周期、历史桶宽、超时、tau、恢复间隔等明确参数。新增 W_s、T_min、A/B 端口队列目标、端口探测速率与突发、每流探测量。提供一份有效配置输出，所有派生值也记录。

首版复用 R3 非粒度相关参数作为实验起点；组队列阈值与组探测参数必须重新映射为端口参数，禁止机械按流复制。具体数值在实现配置中显式确定，论文参数不能由代码默认值隐式决定。

## 9. 实现顺序与对照

1. **R4 基础版**：逐流身份/报告/状态机，A/B 端口分配与逐流整形，旧快照控制；先验证字节守恒、暂停恢复和完成。
2. **R4 历史版**：加入逐流 H_i 和终点重建；旧快照/历史只切换决策使用的队列估计。
3. **服务模型对照**：固定队列模式，比较预算服务估计与第 4.3 节观测模型；不同时改反馈规则。
4. **主机/网关反馈消融**：明确区分旧版未隔离反馈与修订后的 A 边界；边界内部记录 CE 转近端、清除和 A 新标记禁用三项。关闭近端反馈同时清 CE 的组合仅可作为显式有损反馈消融，不能作为正常配置；下游标记保留；B 受控出口新标记禁用。
5. **成本与规模**：机制有收益后增加流数，统计状态、历史桶、控制字节、控制周期耗时和仿真耗时。

history/snapshot 的公平对照使用相同历史有效性条件；若旧快照版仍计算历史，只能用于评估“使用预测值”的增量作用。另设禁用历史维护的成本对照，不能混称零历史开销。

完整历史桶成本近似 O(N*ceil(T_retention/bin_width))，逐流记录 O(N)，报告字节约 O(N_active/T_report)；记录实际结构大小和实际发送报文，不只报告渐近复杂度。

## 10. 验证与完成标准

### 10.1 确定性功能回归

- 每流反应、预算与实际发送分别可观测；一流反馈不直接改另一流的反应状态。
- 一流达到上限后剩余端口份额可重分配；无组数/组内流数依赖。
- 预算与探测总量不超过端口规则；令牌突发造成的短时偏差按桶上界核验，不能要求每个瞬时样本严格等于平均限额。
- 空队列、持续积压、暂停、令牌不足和采样边界下的服务观测正确。
- 应覆盖无数据初始化、全零预算、暂停恢复、报告过期恢复、缺历史、丢失/乱序/重复记录、错误 generation、完成后尾部排空；已存在的回归断言与历史执行结果以实现验证记录为准。
- 两流不同 PG 和同 PG 均可运行；PFC 的共同暂停不误写成控制器主动降速。
- 历史回放覆盖突发、中途排空、边界桶和同纳秒事件顺序，逐流累计字节闭合。

本次修订新增验收：

- 上游 CE 到 A 后被记录并转为近端 CNP，出 A 时为 ECT(0)，DSCP 不变；无 A 积压仍可触发，连续 CE 按流合并且待反馈状态不因限频丢失。
- A/B 受控出口积压不新标记；B 保留已有 CE，下游标记能触发接收端反馈和 B 反应；双向、非受控流、Not-ECT 路径不受误改。
- 活动流在控制采样时空队列，随后到包能按有效许可发送，不形成每 50 μs 的速率零/非零切换；暂停、令牌不足仍阻塞，结束后释放许可。
- 启动前零预算 STATE 不跳过启动；首次活动零预算也能完成接管，过期不重新满速启动；验证单流及多流同时启动的积压、丢包和恢复。
- 先分别验证边界与空队列修改，再验证组合的 M0。核对 FCT、实际 TX/RX 闭合、CNP 来源、网关预算/执行速率、队列/PFC/准入丢弃；不以预算升高或程序退出成功代替性能证据。

### 10.2 最小机制场景

| 场景 | 控制的问题 | 必须观察的证据 |
|---|---|---|
| 单流、无竞争 | 基础开销及恢复 | 供给充足时无长期停滞，字节闭合 |
| 两流共享出口饱和 | 必要的带宽竞争 | 总容量约束、利用率、队列和速率波动 |
| 两跨域流到不同主机，仅一条受本地流竞争 | 选择性 | 反应差异是否进入预算、实际 TX 和接收 goodput/FCT |
| 流加入/退出，或另一优先级暂停/恢复 | 服务变化及不同龄期预算 | 精确终点预测误差、积压峰值、恢复时间 |
| B 有积压与 A 持续有供给 | 历史增量作用 | 估计→注入→实际发送→队列/完成结果 |
| 控制丢失、启动与零速率恢复 | 活性与保守回退 | 有限探测、不无限续发、反馈恢复后能恢复 |

异质场景保持两流真实共享 B 出口，随后在 Spine/Leaf 分流，本地流仅在指定下游路径竞争。反应上限若始终高于端口分配份额，预算可以相同；这种结果只能证明反应状态有差异，不能证明选择性收益。

### 10.3 指标与证据

逐流记录 r_i、b_i、s_i 及来源、q_i、q_i^*、qhat_i、v_i、u_i、实际 TX/RX、报告年龄、暂停、需求、服务窗口、探测量和各类 CNP。端口记录全部受控/非受控 TX、容量估计、利用率、目标总量、缓存保护和控制开销。

预测对齐到 t+d_i 的事件级真实 B 队列，声明同时间戳事件边界；同时报告所有样本与 A 有积压/有真实供给样本，区分正负误差。离线使用未来实际出队的 oracle 只诊断守恒与服务项，不是在线算法，也不是独立预测证据。

完成场景要求期望 FCT 条数、逐流 payload TX/RX、wire 入队/出队、重传/丢弃及最终排空闭合。固定时间观察场景单独报告未完成与残余积压，不伪装完成。基线使用相同拓扑、流量、缓冲、PFC 和计量条件，先验证本身有效。

### 10.4 研究判断与停止条件

- 选择性贡献必须体现为相对统一反应/R3 等明确对照的实际结果改善；预算不同不够。
- 历史贡献必须在有积压、有供给时带来可解释的队列或完成收益；只改变日志或空闲样本不够。
- 若服务误差抵消历史收益，先修正或收缩预测模型，不扩大场景掩盖负结果。
- 若收益来自挤占本地竞争流，报告跨域与本地双方结果和公平参考，不能只报告跨域收益。
- 若正常运行依赖频繁共享保护或持续 PFC，保留结果并定位原因，不主张独立逐流控制已经充分有效。
- 不预先给无依据的收益百分比；先用确定性机制场景判断因果，再用成对重复实验给出分布和不确定性。

## 11. 可写入论文的候选叙事

两条跨域流共享 WAN 和 B 出口，但下游竞争不同。R4 在 B 保留逐流反馈与预算，在 A 对每条流使用实际发送历史估计反馈延迟期间的积压，并由各端口协调共享容量。逐流化避免把单流积压直接转换成全组排空惩罚，但共享资源、PFC 和主机反馈仍可产生耦合。

候选贡献是逐流远端状态与已发送输入的协调方法及其受共享资源约束的收益/成本，不是“去掉组”本身。新颖性需要后续核对相关论文；本设计没有新增文献检索，也不声称已经证明区别于所有现有算法。

修订后仍保留的主要限制：B 反馈不定位远端域内具体拥塞点；主机与网关串联控制；服务份额变化不可预知；固定时延/时钟；预算不是容量预留；逐流状态和队列的硬件成本待评估。

## 12. 本次交付与实施边界

本文固定 R4 第一版的架构、候选服务模型、控制律、协议、异常规则和验收顺序。参数起点仍需随实现输出明确配置，性能结论须经验证。后续若改变服务公式、反馈归属或控制对象，应记录设计修订，避免把不同算法混入同一 R4 结果。
