# 统一六算法快速实验：代码审计与最小修改计划

入口固定为 `crossDC-evaluation-workload.cc`，沿用当前拓扑读取、地址分配、路由、RdmaClient和QP。复用 `run_scripts/run_single_workload_algo.py`，不另建仿真入口或拥塞控制类继承框架。

## 已确认的结构

| 项目 | 位置与行为 |
|---|---|
| 算法选择 | workload入口 `--algorithm` / 配置`CC_MODE`；目前CLI默认值会覆盖配置，需要只在显式传参时覆盖 |
| 公共接口 | `RdmaHw`接收ACK/CNP/ICMP，`SwitchNode`交换机反馈，`RdmaQueuePair`保存速率/窗口状态；没有独立的通用算法基类，无需新建 |
| DCQCN/HPCC/TIMELY | 模式1/3/7；分别由ECN、INT、RTT反馈驱动；既有`ChangeRate`也有直接更新`qp->m_rate`的路径 |
| Bifrost | 模式12已接入，但原暂停时间固定50µs，接收路径缺少到期恢复；需要补齐，不能直接标为论文实现 |
| FRP | 模式13已实现`FrpRateCalculator`、交换机ICMP反馈与`HandleFrpFeedback`；以仓库版本为基准，论文归属尚待确认 |
| Proposed | 已有`longhaul-research.h`实现，需适配当前workload入口及集中参数，不复制另一套框架 |
| TX | `RdmaQpDequeue`是真实发包trace；`qp->m_rate`只是控制状态 |
| goodput | `RdmaRxQueuePair::m_recv_bytes`为按序有效接收字节；现有`PrintResultsFlow`输出stdout |
| BIF | `GetOnTheFly()` / snd_nxt−snd_una，注意重传回退语义 |
| RTT | TIMELY处理ACK的时间戳；基础pairRtt不是实际RTT采样 |
| Queue/ECN/PFC | `QbbEnqueue/QbbDequeue/QbbPfc`和SwitchMmu；旧monitor_buffer只定义/递归，未找到启动调用 |
| FCT | 通用FCT为原始值；query专用文件会按硬编码DC范围减RTT |
| 配置/输入 | `config-workload.txt`、TOPOLOGY_FILE、QUERY_FLOW_FILE；背景CDF可禁用 |
| Python | 现有workload runner兼有运行、日志解析和matplotlib绘图；REPO_ROOT误指run_scripts目录，须修正 |

## 公平性与正确性风险

- 查询流全部完成后会提前停仿真，不能直接用于统一时长的动态实验。
- 查询流按硬编码节点范围判定跨DC，并对“本地流”加开始偏移；小拓扑要使用真实流文件时刻。
- 当前地址划分使用交换机间链路延迟阈值1ms；快速实验需满足其约定，或明确配置DC边界。
- FRP存在跨QP共享的静态最小速率状态、散落参数、int16队列偏差溢出风险。
- Bifrost属于逐跳流控，不能把它当作单纯RNIC调速算法；需说明其端侧保留的传输控制。
- 动态增减流不能靠所有算法相同字节数来保证相同退出时间；需统一停止注入时刻，并区分源端停止与接收侧在途排空。

## 最小改动文件

1. `crossDC-evaluation-workload.cc`：参数覆盖、快速实验开关、原始FCT/固定停止时间、统一观测及proposed接入。
2. `switch-node.{h,cc}`：在现有Bifrost分支补Algorithm 1入口状态与暂停控制；复用FRP路径。
3. `qbb-net-device.{h,cc}`：暂停时间到期恢复、刷新计时器及重复XON处理；六算法共用修正后的链路层。
4. `frp-rate-calculator.{h,cc}`、`rdma-hw.cc`：集中FRP参数，修正状态作用域和字段范围。
5. 既有`longhaul-research.h`：参数集中与最小预测保护；适配接入而非另建入口。
6. `run_scripts/run_single_workload_algo.py`：增加`--cc/--scenario`，保留旧位置参数；生成隔离配置/小流文件、统一绘图。
7. 少量快速实验配置/结果文档，不修改原workload输入来跑小实验。

## 快速实验初始建议（待运行后定稿）

双DCI小拓扑，2/4/8源主机、一个接收瓶颈出口。跨域单向1ms，使2ms反馈环路能够在几十毫秒内观察多轮；跨域100Gbps，接收瓶颈50Gbps，主机100Gbps，域内1.5µs。具体buffer必须同时满足Bifrost名义Delta+2RsT，并对所有算法一致；不能为了让某个算法通过而单独改变物理buffer。

basic：2流；incast：4或8流同时加入；dynamic：2→8→2，固定额外流停止注入时刻。FCT只比较真正完成的流，中途停止的诊断流明确标为截断，不能当作完成。

所有模式保留相同拓扑/输入/停止时刻/窗口/ECN阈值/物理buffer/统计口径。Bifrost在指定端口替换标准PFC决策，这是算法机制差异，需要记录。
