## 4. 必须调整：实验用途与 S2/S3/S5 竞争关系

### 4.1 默认 S2：区分瞬态观察和有限流完成

**依据：**Review P0-1。七条流在 0.21 s 启动，到 0.38 s 仅剩 0.17 s；3 GB payload 即使独占 100 Gb/s 链路也至少需要 0.24 s，尚未计入竞争、头部和传播时间。

**建议：**

1. 保留 0.38 s 作为明确标注的瞬态观察设置，不将其结果当作完整 FCT 比较。
2. 完成实验单独通过现有 runner 的 `--stop-times` 指定时长。README 中的 1.50 s 仅为候选，后续依完成数、剩余数据与队列核验是否充分。
3. 修正 README 中“默认 S0”的描述，并明确默认算法、场景和用途。
4. 每次运行记录属于瞬态实验还是完成实验，提前固定停止规则，不按算法表现分别选择有利时长。

**预期解决：**区分停止过早与算法控制效果。

**验收：**完成实验具有预期/完成/未完成流清单；瞬态实验报告未完成数量和已接收字节，不仅对完成子集给出 FCT 排名。具体充分时长待核实。

### 4.2 缩小场景：保留关系，不统一缩为同样大小

**依据：**Review P0-2 的历史记录：S2 首流在新流加入前结束；S3 变成八条等长流；S5 背景在探测流到达前结束。这些记录仍可用于功能检查，不能证明目标竞争关系。

建议保留正式输入，另建明确标识用途的缩小流文件。

| 场景 | 建议改什么 | 成立条件及后续验证 |
|---|---|---|
| S2 加入 | 联合设计首流大小、七条流加入时刻和加入后窗口 | 加入时首流还有待发送数据；加入后存在共同竞争阶段 |
| S3 退出 | 保留七条较小流与一条较大流；正式比例为 625 MB : 3 GB | 依据实际发送和完成记录识别退出；剩余流在退出后继续供给 |
| S5 共存 | 保留背景与探测流大小区别，调整缩小后的背景大小或探测到达时刻 | 每条探测流到达时背景仍在传输；若主张稳态叠加，另核验背景稳定性 |

**参数选择约束：**

- 先定义要观察的事件与窗口，再选择流大小、开始时刻和停止时间；具体数值待小规模校验。
- 不按字节缩小比例机械缩短全部时间：WAN 延迟和控制周期并未同步缩短。
- 对持续供给窗口，可用接入链路最大速率计算流大小的保守下界，再由实际发送记录验收。仅未收到完成 ACK 不足以证明还有待发数据。
- 算法间使用相同输入；若某算法下目标关系不成立，应明确标记，不单独修改其负载。
- 当前收敛保持时间为 `max(3 × 基础 RTT, 20 ms)`，跨域约 30.7 ms，可作为观察窗口设计的现有约束。是否沿用该判据及容差需在实验前固定。

**依赖：**明确观察阶段，并具备能区分供给结束、接收完成和控制恢复的统计。大小比例本身不保证实际退出顺序，必须验收。

## 5. 必须调整：统计口径

**依据：**Review P1-2；前序源码核对确认简单同向均分、方向混合、停止前窗口与忽略非数值未收敛项仍存在。

### 5.1 实际路径与公平参考

- 不再以“单流路径瓶颈 ÷ 同向活跃流数”作为统一公平目标。
- 按实际有向路径、共享链路容量与活跃集合建立约束。明确公平准则；若采用 max-min 分配，将其标为分析参考，不声称协议保证达到它。
- 统一 wire 容量与 payload goodput 的口径，说明头部和其他流量的处理。
- 当前公共元数据只有跳数、瓶颈速率等摘要；R3 的 `r3.paths.csv` 包含跨域路径但跳过本地流。新增本地竞争流后必须补齐其路径证据，不能只凭拓扑邻接或旧 2/5/1 分组推定。
- 如路径条件尚不具备，暂缓输出具有结论性的公平/收敛判断，不用简单均分替代。

### 5.2 方向、阶段与队列

- S4 分别输出 A→B、B→A 的利用率与队列。
- 区分全运行区间、预先定义的竞争区间和事件后的观察区间；不得只用停止前窗口代表整体。
- `dci_queue_max_bytes` 改为明确的全程采样最大值，或将原值明确命名为尾窗最大值。
- 采样峰值与逐事件峰值分开；WAN 出口、B 向内出口和下游瓶颈队列分开。
- 避免把流完成后的空闲尾段解释为算法低利用率，也不能事后挑选最有利窗口。

### 5.3 未完成、未收敛与不足样本

- 输出预期、完成、未完成流数及逐流状态。
- 输出各阶段可评估数量、未收敛比例；收敛时间中位数标注为已收敛子集。
- 观察窗口不足单列，不与充分观察后未收敛混合。
- 流退出或供给结束后不继续作为持续需求流参与公平评价。

**验证方式：**先用小型已知路径样例核对容量分配，用含未收敛和不足窗口的样例核对汇总，再用静态记录核对方向与窗口。无需先开展完整性能实验。

## 6. 建议增加：最小 R3 机制场景

**依据：**Review P1-1、P0-3 和 §5–6。

建议新增 `simulator/ns-3.39/examples/LonghaulCC/flow-longhaul-r3-mechanism.txt`（拟定名称，尚未创建），沿用现有层次拓扑。

### 6.1 场景构造

1. 两类持续供给的跨域流经过同一 B 向内出口、同一 PG，随后走向不同下游分支或接收出口。
2. 添加接收 DC 内的有限竞争流，仅与其中一类跨域流共享目标下游瓶颈。
3. 设置明确的竞争启动时刻；竞争结束以实际传输记录确定。
4. 核验另一类流不经过该目标瓶颈，且跨域反馈回程仍经过 B。

具体主机 ID、端口和流大小待路径核验后确定。不同接收主机不自动构成异质对照；构造中仍可能存在共享上游和 PFC 影响，需要记录，而不能预设完全隔离。

### 6.2 最小比较集合

| 对照 | 目的 |
|---|---|
| 无本地竞争的完整 R3 | 识别新增竞争造成的变化 |
| 有本地竞争的完整 R3 | 检查逐流反应、服务估计和预测执行 |
| 有本地竞争、使用旧快照队列的 R3 | 检验发送历史重建的增量作用 |

该场景是建议调整；若准备主张预测收益，相应消融和证据链属于必须完成的条件。

### 6.3 消融实现边界

当前没有现成的预测消融开关，需要修改网关配置、`UpdateSource()`、入口配置解析及元数据。配置键名在实施时确定，不将拟定开关写成现有能力。

最小定义：只把预算公式中的重建队列替换为最近有效快照的队列值；保留 B 逐流反应、快照传输、预算分配、真实整形、RNIC DCQCN，以及相同的超时和历史有效性条件。默认行为仍为完整 R3。

不通过抬高 `qref` 或关闭整个整形器代替对照，否则改变的不只是预测。该比较能够检验历史重建的增量作用，但不能单独隔离 B 逐流反应的贡献。

### 6.4 证据链与观测

需要连接：

> 下游竞争开始 → 对应流反馈与 B 预算变化 → A 预测及最终预算变化 → A 有待发数据时实际出队变化 → B 队列与接收 goodput/FCT 变化。

优先复用 gateway、packets、paths 日志；无法识别快照、预测终点、最终限额或暂停限制时，才添加必要字段。

- `queue_bytes` 是逐流值，判断 A 组是否积压要按组求和。
- 组预测值重复出现在逐流行中，不得累加。
- 按前序核对的 `History::Predict()` 时间映射，A 在 `t` 时刻的预测对应模型中的 B 时刻约 `t + forward_delay`；不能与 B 在 `t` 时刻的队列直接比较。
- 实际排队、到达偏差和采样误差单独分析；比较同一受控组的字节口径。
- 同时检查预算、PFC、其他容量约束与源端供给，辨别实际发送为何变化。

**进入收益比较的条件：**目标下降期间 A 有待发数据，并能判断最终限额是否影响实际发送。若只有预测数值变化，或差异被其他约束覆盖，报告尚未形成可判别效果，不降低阈值强行制造收益。

若预测持续明显失配，先定位时间对齐、服务估计或需求变化，再讨论参数修改。没有性能差异或效果变差也属于有效结果，不自动扩大规模重试。

## 7. 比较前必须核验：baseline、资源与结果来源

**依据：**Review P1-3、§4.2–4.3。

### 7.1 baseline 与缓存

- 先用 DCQCN 与完整 R3 验收场景，再加入消融。HPCC、TIMELY、Bifrost 在对应拥塞负载下完成有效性核验后再比较。
- 检查控制信号、窗口约束、暂停、丢弃与实际传输。TIMELY 当前阈值可作起点，但不能称已标定。
- 报告共享缓存及逐端口、逐 PG headroom。按当前公式，WAN 每 PG 为 375,000,000 B，DC 内 100 Gb/s 端口每 PG 为 56,250 B；不能把 `BUFFER_SIZE 50` 解释成全系统只有 50 MiB。
- headroom 公式未包含 `NIC_DELAY`；本文不拍定新的正确值。若准入丢弃影响比较，先核查暂停传播与接收处理，再统一调整资源条件。
- R3 的 `r3.summary.json` 仅在 R3 模式生成。各算法应具备等价的全网丢弃和残留统计；不足时补最小公共记录，而不是仅比较网关局部计数。

### 7.2 完整性与可追溯性

- 保存有效配置、输入与拓扑哈希、命令、seed/run、源码版本及未提交差异标识，确认构建产物与源码对应。
- 复用现有 runner 参数和每次运行目录；不覆盖历史结果，不把变化中的结果目录纳入正式比较。
- 检查预期 FCT 数、重复记录、未完成流、唯一接收 payload、发送 payload、重传、网关 wire 字节及残留。
- 重传发生时不强求原始 TX payload 等于流大小；网关计数按观察点、丢弃和残留解释。
- 程序正常退出、CSV 生成或 `status=ok` 不构成性能验收。

重复次数待核实随机来源和配对运行方式后确定。固定负载下反复得到相同结果，不能自动增加独立样本量。

## 8. 实施顺序与阶段验收

| 阶段 | 实施内容 | 可检查结果 | 进入下一阶段条件 |
|---|---|---|---|
| 1. 固定定义 | 区分瞬态/完成用途，定义事件窗口，修正文档默认场景 | 场景表、输入清单、窗口和完成条件 | 各场景有明确研究问题和判据 |
| 2. 修正统计 | 路径参考、方向、窗口、完成与收敛状态 | 指标字段及小型校验样例 | 不把尾窗、混合方向或成功子集当整体 |
| 3. 验收缩小场景 | 后续运行 DCQCN/R3 最小必要测试 | 加入重叠、退出后供给、背景与探测重叠证据 | 关系成立；否则调整输入，不评价算法优劣 |
| 4. 验收机制场景 | 核实异质路径，比较完整 R3 与旧快照对照 | 对齐的状态、决策、实际动作及结果 | 能判定预测是否改变发送；无差异如实保留 |
| 5. 扩展性能比较 | 核验 baseline、正式负载和重复设计 | 完成率、队列、goodput、FCT、丢弃及不确定性 | 仅对可信条件与有效样本下结论 |

阶段失败应回到对应输入、测量或机制问题，不直接扩大算法和参数矩阵。阶段 3–5 的运行均为后续工作，本文生成没有执行这些步骤。

## 9. 暂不调整的事项

- 保留真实 host→leaf→spine→DCI 层次拓扑，不改为主机直连 DCI。
- 保留 S0 启动成本检查、S1 同步竞争和 S4 双向反馈检查的角色。
- 不立即新增完整 incast 矩阵、大规模 RTT/带宽/流规模扫描或全面算法比较。
- 不重构路由、控制器整体结构或运行框架。
- R3 周期、`qref`、`tau` 等先保持当前值作为起点，待证据指出问题再讨论调整。
- 不将历史实验结论改写为 R3 结果，不为缺失旧文件重建无关历史环境。

## 10. 研究主张与剩余证据

| 可更可靠检验的主张 | 所需证据或边界 |
|---|---|
| S2 加入后的冲击与恢复 | 真实共同竞争、正确路径参考、充分窗口 |
| S3 退出后的带宽再获取 | 剩余流确有供给；不能只用最终完成时间代替恢复过程 |
| S5 长短流共存表现 | 四条探测流不足以支撑可靠尾延迟主张，需后续样本设计 |
| 历史重建相对旧快照的增量作用 | 相同机制消融、实际发送差异、对齐后的队列误差和性能结果 |
| 异质下游拥塞下的逐流响应 | 路径与拥塞位置证据；独立归因于逐流机制还需额外机制对照 |
| 指定资源与负载下的传输完整性 | 全网丢弃、重传、残留及逐流核验，不能外推为普遍无损 |

即使完成本方案，也不能仅凭这些场景证明理论稳定性、普遍最优、公平性保证或优于全部 baseline。B 观察到的 CNP 仍是路径拥塞反馈，不能自动解释为只来自 B 内部。
