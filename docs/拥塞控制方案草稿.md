# LSCC 执行偏差补偿方案

拥塞控制方案 v0.4　研究设计稿　2026年9月10日

本文针对 LSCC 的一个具体问题展开：接收侧已经发出目标速率，发送侧却仍需通过伪队列、direct CNP 和 RNIC 拥塞控制逐步完成调整。当实际发送没有按预期跟上目标时，基于反馈列表的时延补偿可能失准。本方案保留 LSCC 的分段控制与近源执行路径，用发送侧实际进入长链路的字节记录校准执行模型，再据此计算后续目标速率。

核心思想是：**补偿依据应从“已经要求源端改变多少”，推进到“已有证据表明源端实际改变了多少，以及尚未观测的部分可能怎样变化”。** 接收侧已有真实队列，不再依赖发送侧重建整个远端队列。实际发送摘要用于校准执行过程，不能突破传播时延，也不能被当作先于数据到达的观测。

本文中，“论文事实”指 LSCC 原文明确给出的机制或条件；“分析”指由机制得到的判断；“候选设计”指本版提出的方案；“待验证”指仍需实验或证明支持的性质。本文不报告性能收益，不声称已经证明稳定、无损或新颖性。

## 1 研究问题与方案边界

### 1.1 LSCC 已经解决了什么

**论文事实。** LSCC 在两侧 DCI 建立分段反馈。接收侧计算虚拟瓶颈速率，发送侧把该速率作为伪队列的排空速率；伪队列超过阈值时，向选定源流发送 direct CNP。RNIC 沿用 DCQCN 逐步调速。普通 CNP 仍保留，用于多瓶颈等条件下的反馈与公平性。[1，§III-B，PDF 第3—6页]

LSCC 已经维护尚未生效的速率修正列表。若长链路 RTT 为 $2D=NT$，原文式(2)可写成：

$$
u_k=\overline C_k-\frac{q_k-q_{\mathrm{ref}}}{T}
       +\sum_{j=1}^{N}R_{a,k-j}.
$$

其中 $R_a$ 是原文的速率修正项。Algorithm 1 在步长限制与限幅后重新记录 $R_a=\overline C-u$，并非直接记录未经执行约束的初始计算值。反馈列表的作用是避免对仍在传播中的修正重复反应。

**本方案不能把“存在反馈列表”“考虑尚未生效的反馈”或“增加预测”作为新贡献。**

### 1.2 尚需验证的失配

**论文事实。** LSCC 式(5)的推导使用了接收反馈后立即采用目标速率的理想化条件。原文随后解释，实际源端逐步收敛，如果能在一个周期 $T$ 内稳定下来，便可近似满足该条件。因此论文采用 $T$ 和相邻反馈变化上限 $\Delta R$ 约束执行过程；示例中 $T=200\,\mu s$，且式(12)把 $\Delta R$ 的上限与共存流数、DCQCN 加速能力联系起来。[1，PDF 第4—6页]

**分析。** 源端的实际跟踪能力会随活跃流数、已有 DCQCN 状态、源侧竞争和应用供数变化。固定周期和固定步长可能在部分状态下过于保守，在另一些状态下又不足以支持原先的近似。这个问题需要先复现，不能因推导采用近似就断言原算法失效。

本研究具体检验：**在流量和执行状态变化时，目标速率与实际发送量的失配，是否足以解释经过调参的 LSCC 仍存在的队列过冲、排空和恢复迟缓？实际发送信息能否以可接受成本减少这些损失？**

### 1.3 一个量纲示例

假设反馈要求将聚合速率从 100 Gbit/s 降到 60 Gbit/s，但下一段 200 μs 内实际平均发送速率为 85 Gbit/s。该段相对于目标的发送偏差为：

$$
e_B=(85-60)\times10^9/8\times200\times10^{-6}
    =625000\ \mathrm{Byte}=0.625\ \mathrm{MB}.
$$

这说明短时间的执行失配也能对应可观的字节量。但这 0.625 MB 不一定全部成为额外物理队列：还取决于当时的服务、已有空闲和其他到达。它抵达之后，其队列影响已经包含在接收侧实测队列中，不能再把同一偏差叠加到当前队列。

### 1.4 首版研究场景

首版采用一对 DCI、固定且可辨识的长链路，以及 LSCC 原有的聚合控制对象。多个 RNIC 经发送侧 DCI 注入同一受控类别；接收侧能够统计该输入对应的驻留字节和出队字节。下游竞争通过该聚合对象实际获得的服务体现。

初版假设长链路内没有未观测的中间缓存变化、丢包和重路由，并明确时钟误差范围。源端流加入退出、应用受限和源侧竞争属于必须测试的执行扰动；远端服务变化属于另一类扰动，应分别注入，避免混淆。

不把场景进一步收窄为“固定容量、独占队列、所有流永远饱和”，因为这可能让简单整形已经足够。也不在首版同时解决多 DCI 汇聚、多路径、全局逐流公平与可靠传输。

## 2 相对 v0.3 的收敛

| 项目 | v0.3 | v0.4 |
|---|---|---|
| 研究主线 | 发送侧预测远端队列并向 RNIC提供共同状态 | 校正 LSCC 的执行过程与反馈补偿 |
| 真实队列的位置 | 接收侧测量，发送侧回放 | 接收侧直接作为每轮预测起点 |
| 实际发送记账 | 预测远端到达 | 对齐目标和执行，校准未观测到达的模型 |
| 输出 | RNIC 计算 $R/N$ | 仍向发送侧 LSCC 伪队列下发聚合目标 $u$ |
| 公平机制 | 拟引入共同流数与显式份额 | 保留 LSCC 原机制，公平仅作验证指标 |
| 主要新增状态 | 队列镜像、竞争规模和误差 | 版本账本、发送时间桶、少量执行参数 |

**候选设计。** 首版只替换 LSCC 外层的补偿预测与目标更新逻辑，不额外并行运行一套队列 PI 控制器。direct CNP 的生成规则、源流筛选和普通 CNP 配置先保持原实现，避免同时改变多个因素。已存在的逐流状态不会因为新增状态按聚合计数而消失。

## 3 控制对象与时间轴

### 3.1 三种量必须分开

本方案使用以下口径：

- $u(t)$：发送侧当前采用的伪队列目标排空速率，是控制输入，不是实际数据面的硬整形速率。
- $X(t)$：发送侧 DCI 在长链路出口真正发出的累计数据字节。
- $A(t)$、$D(t)$：接收侧受控队列对象的累计到达与实际出队字节。

发送侧伪队列仍按“进入该发送队列的字节减去 $u\delta$”更新；执行观测必须按 $X$ 统计。发送侧有真实缓存时，进入队列的速率不等于长链路发送速率，不能混用。

接收侧 $q(t)$ 沿用 LSCC 的输入聚合驻留字节口径；它可能由 MMU 统计多个输出方向上的驻留数据，不自动等同于某一个物理出口队列。其服务应为同一批受控流量实际获得的出队服务，不能拿整个端口的所有出队流量替代。

### 3.2 时延定义

设接收侧在 $t_k$ 发出命令 $u_k$。控制报文到发送侧耗时 $d_b$；发送侧登记并切换伪队列目标后，近源反馈和 RNIC 动作存在局部起效死区 $d_0$；数据返回接收侧耗时 $d_f$。

$$
L=d_b+d_0+d_f.
$$

$L$ 表示本次命令最早可能影响接收侧到达的时间，不表示发送已经收敛。起效之后的渐进收敛由执行模型描述，不能再把完整收敛时间重复加进 $L$。

原文的 $2D$ 是长链路往返时延；本方案显式保留局部执行死区。首版测得 $d_0$ 后固定使用；在线只估计少量执行参数，不同时自由拟合时延和响应速度，以降低不可辨识性。

### 3.3 摘要不具备超前观测能力

时间线如下：

```text
接收侧：发出 u_k -------------------------------------- 观察其到达影响
               d_b                 d_0 与渐进响应          d_f
发送侧：          登记版本 → 改变伪队列目标 → 实际发出数据
                                              └→ 发送执行摘要
```

如果摘要和数据经过相同传播路径，摘要通常不会比所描述的数据更早到达；周期末生成还会增加等待。摘要的作用是提供“数据对应哪个目标、何时登记目标、当时处于什么执行状态”，帮助区分执行失配、服务变化与对齐错误。

**在固定无损链路上，接收侧到达计数已经包含延迟后的实际发送信息。** 因此必须设置“只用接收侧到达计数”的对照。若增加发送摘要并未改善对齐或状态识别，应删除冗余字段，不能把双端记账本身作为不可替代的贡献。

## 4 命令与执行账本

### 4.1 命令记录

每个控制对象 $g=(\text{源DCI},\text{长链路},\text{业务类别})$ 单独维护命令序列：

```text
Command = {group, path_epoch, command_id, issue_time, target_rate, expiry}
```

发送侧采用当前路径版本中最新且有效的命令。重复命令不重新初始化伪队列，不额外触发一次惩罚；乱序旧命令不覆盖新目标。反馈丢失时延续最近有效目标并报告该版本，不假装缺失版本已执行。

路径版本与命令序号不能相互替代。版本表示命令属于哪条有效路径和计数会话，序号表示该会话中的命令先后。

### 4.2 发送时间桶

用较细粒度 $\delta$ 记录实际发送。控制周期为 $T$，报告周期为 $T_s$，三者分开设置，且首版取 $T$ 为 $\delta$ 的整数倍。

对桶 $I_j=[s_j,s_j+\delta)$：

$$
X_j=X(s_j+\delta)-X(s_j),\qquad
U_j=\int_{I_j}u(s)\,ds,\qquad
e_j=X_j-U_j.
$$

$e_j$ 是字节偏差；$x_j=X_j/\delta$ 与 $\bar u_j=U_j/\delta$ 是平均速率。它描述该时段的结果，不代表该时段全部变化都由一个命令因果触发。

**版本已登记不等于版本已完成。** 不能把“current command_id”标成“执行完成的命令”。

首版在桶边界切换目标，额外等待不超过 $\delta$，计入登记时延；这样一桶只对应一个目标。若后续需要即时切换，必须分段积分 $U_j$，不能用桶末目标乘整个桶长。

### 4.3 摘要字段与发送规则

```text
ExecutionReport = {
    group, path_epoch, report_seq,
    source_interval_start, source_interval_end,
    cumulative_tx_bytes, target_byte_integral,
    registered_command_id, command_install_time,
    recent_bucket_records,
    pseudo_queue_state, pause_or_backlog_flags
}
```

发送摘要包含：该段实际字节、目标积分、登记版本和少量状态。细桶记录的数量单独决定报文长度，不能在只发送一个周期总量时声称接收侧掌握了全部微突发时序。

基线实现每 $T_s=T$ 发送，版本变化和显著跟踪异常可以触发提前上报，但设最小间隔。不能只依赖数据携带摘要，否则无数据和发送受阻时无法区分报告丢失与实际零发送。空闲时保留低频心跳。

累计计数器用于去重和恢复总量。中间摘要丢失后，后续计数差分可恢复跨段字节总数，不能恢复丢失细桶内的分布；这部分历史仍应标为时间分辨率不足。

## 5 执行偏差的解释

### 5.1 三类偏差

| 现象 | 可能原因 | 控制上的处理 |
|---|---|---|
| 实际发送高于目标 | 降速尚未完成、已有源侧积压正在释放 | 修正未来执行预测，限制持续过量注入 |
| 实际发送低于目标 | 加速尚未完成、应用无数据、源侧拥塞、PFC 暂停 | 先区分可控跟踪与供数不足，不能补发历史欠量 |
| 实际到达不同于延迟后的发送 | 时间对齐误差、链路排队、丢包、路径变化 | 降低模型置信度，不直接解释为 RNIC 执行能力变化 |

仅靠发送字节不能可靠判断“应用没数据”与“RNIC 正在限速”。伪队列、CNP 活动和暂停标记只能提供辅助证据。不能声称无需额外需求信息就能完成精确分类。

### 5.2 不设可兑现的欠发送账户

当 $e_j<0$ 时，不给源端积累以后可补发的信用。应用恢复时可能突然具有很高需求，历史负偏差不代表远端仍有可供突发使用的空闲。

历史超发也不作为永久扣款。已到达部分由接收侧真实队列反映；只有仍影响未来的执行状态进入预测。不存在“真实队列加累计执行误差”这一控制变量。

### 5.3 不强行分解每条命令的效果

命令可能在源端完全收敛之前就再次更新，其响应相互重叠。首版维护按时间排序的目标轨迹和实际发送轨迹，不计算“第 k 条命令已经完成了百分之几”这样的独立归因。

时间与版本的作用是保证输入输出对应正确，而非让所有动态变化都能归因到单条命令。伪队列的历史、DCQCN 状态和需求变化无法由一个版本号编码。

## 6 接收侧预测器

### 6.1 真实队列每轮重新锚定

每轮控制从接收侧当前实测 $q_k$ 开始，只预测此后到达和服务：

$$
\hat q_{i+1}=\left[\hat q_i+\hat A_i-\hat C_i\delta\right]^+,
\qquad \hat q_0=q_k.
$$

每桶非负截断，不能把空闲服务积累到未来。$\hat C_i$ 是该受控对象在队列有需求时预计可获得的服务能力；历史实际出队可用于校准，但队列为空时的低出队量不能直接当成低容量。

收到历史摘要后，先校准历史目标—发送—到达之间的关系，再从新的实测队列重算未来。不要修改实测队列来“补回”旧发送偏差。

### 6.2 最小执行模型

**候选设计。** 用一个分增减方向的一阶模型，近似“伪队列、direct CNP、RNIC 与源侧网络”组成的聚合执行器：

$$
\hat x_j=(1-g_\sigma)\hat x_{j-1}+g_\sigma\bar u_{j-d_0/\delta},
\qquad 0<g_\sigma\le1.
$$

当有效目标高于前一状态时用 $g_\uparrow$，否则用 $g_\downarrow$。时间不对齐时按实际时间插值或切桶，不能直接把非整数死区四舍五入后隐去误差。输出限在物理发送能力范围内。

该模型只是待验证的低阶近似，不是 DCQCN 的精确方程。伪队列阈值造成的死区、已有队列的记忆和应用受限都可能使它失效。模型不可信时进入第9节的保守模式，不继续追求精确反演。

对时间对齐且无已知暂停、路径异常的样本，令 $z_j=\bar u_{j-d_0/\delta}-x_{j-1}$、$y_j=x_j-x_{j-1}$。在同方向的有限历史窗内估计：

$$
\hat g_\sigma=
\operatorname{clip}\left(
\frac{\sum_j w_jz_jy_j}{\sum_jw_jz_j^2},
g_{\min},1\right).
$$

分母太小、样本方向不一致、需求受限可疑、或模型残差持续偏大时不更新该方向。保留原估计并降低置信度。权重只用于有限历史平滑，不把低发送一律拟合成“加速很慢”。

参数最多每个预测时域更新一次；一轮求解期间参数固定。首版不叠加卡尔曼、神经网络或同时在线拟合多个隐状态。

### 6.3 如何使用已确认和未确认的记录

预测器保留三种状态标签：已确认的实际发送桶、已登记但尚未确认实际结果的目标桶、登记情况仍未知的命令桶。

从最新可用的实际发送样本开始，按已知的目标登记轨迹回放执行状态；空缺部分使用执行模型。登记未知时按控制路径估计到达时间，若报文丢失或时效不明则增加不确定性。再将发送侧轨迹按 $d_f$ 映射为接收侧预计到达。

已确认的历史桶主要用于重新估计执行状态。通常它们对应的数据已经抵达接收侧；这些桶不能再次加入 $q_k$ 之后的到达预测。只有明确落在未来时间区间的记录才可作为未来到达使用，本方案不假设这种超前记录一定存在。

### 6.4 服务与执行分别估计

执行模型由目标和实际发送训练，不用总队列残差同时拟合发送执行与下游服务。服务变化则由接收侧同口径的出队、积压和暂停状态更新。

如果其他流直接进入同一个计数队列，应额外记录其到达，或者限定观测对象；若其他流只竞争调度服务，则其影响体现在 $\hat C$ 中，不能再重复扣除一遍交叉流量。

## 7 带执行模型的目标速率计算

### 7.1 先处理不可撤销部分，再处理可调部分

每个周期 $T$ 选择一个新目标 $u$。在前瞻区间内，过去已发命令按其登记时间继续生效；当前候选命令按预计传播和局部死区起效。在预测终点前假定不再发新的命令，下一控制周期用新的观测重新计算。这是滚动预测中的明确假设，不表示实际永远保持该命令。

预测时域为：

$$
H=L+T_c.
$$

$T_c$ 是允许新目标影响队列的调整窗口，不等于报告周期。它至少为 $T$；执行变慢时需要适当增大，但设定上限，不能用无限扩大预测窗口掩盖执行器失效。超出上限进入保守模式。

在固定模型与固定服务预测下，对每个候选 $u$ 计算：

$$
F_k(u)=\hat q(t_k+H;u),\qquad
P_k(u)=\max_{0\le h\le H}\hat q(t_k+h;u).
$$

目标是让终点队列接近 $q_{\mathrm{ref}}$，并检查期间峰值。仅检查终点可能漏掉“先溢出、再排空”的轨迹。

### 7.2 一个可实现的标量选择规则

在允许目标区间 $[u_{\min},u_{\max}]$ 内，选择满足下列条件的最大目标：

$$
F_k(u)+E_{\mathrm{end}}\le q_{\mathrm{ref}},
\qquad
P_k(u)+E_{\mathrm{peak}}\le q_{\mathrm{guard}}.
$$

$q_{\mathrm{guard}}$ 应低于受控对象实际可用缓冲额度，且共享缓冲变化会改变该额度。$E$ 由已记录的、同一预测时域上的预测残差和时间对齐误差估计；它是经验裕量，未经扰动上界证明不能称为确定安全保证。样本不足时用预先设定的保守值并限制增速。

固定方向增益为正的一阶模型、与候选无关的服务预测及逐桶非负截断，使预测队列随候选目标单调不减。故首版可用固定次数二分查找，例如 8 次，而不需要多变量优化器；最终应返回已检查可行的下端点，不能返回未经检查的中点。若使用了非单调的新模型，不能继续沿用该求解条件。

若全部候选均满足，取上端点；若连下端点也不满足，输出最低可执行目标并报告“本轮无可行预测”，不能宣称队列已受到保证。若约束违反发生在新命令作用前，当前动作无法撤销这部分风险，仍由缓存/PFC等原有机制承担。

### 7.3 不让目标消化速率超过执行能力

实际使用的候选区间同时受物理上下限和非对称步长约束：

$$
u_{\min}=\max(R_{\min},u_{\mathrm{last}}-\Delta_\downarrow),
\quad
u_{\max}=\min(R_{\max},u_{\mathrm{last}}+\Delta_\uparrow).
$$

从可信的执行轨迹中估计每个方向单位时间的跟踪速度 $v_\sigma$，构造：

$$
\Delta_\sigma=
\operatorname{clip}(c\,\hat v_\sigma T,
\Delta_{\sigma,\min},\Delta_{\sigma,\max}),\quad 0<c\le1.
$$

这是经验信任区间，不是执行能力硬保证。样本不足时使用离线校准的固定步长。已有命令仍在传播时，区间以最近发出的目标为中心，不能忘记在途命令而从旧观测速率重新开始跳变。

需求受限、暂停或长期不能跟踪时，冻结经验增速能力的更新，撤销未证实的乐观增速；不得把负偏差转换为额外发送额度。与此同时保留有界恢复探测，防止低速状态因无样本而永久锁住。探测仍受峰值检查与最小间隔限制。

### 7.4 紧急减速与一般调节

当实测队列达到紧急水线，或已检测到服务显著下降时，可跳过通常的减速步长约束，发出最低目标。紧急规则在所有相关基线中同样启用，不能把它的收益计为执行模型收益。

最低目标也不是即刻停止发包。它只是改变伪队列排空速率，RNIC 仍需响应。$R_{\min}$ 首版沿用基线配置；能否取零、取零后的恢复和普通 CNP交互，必须另行验证。

## 8 与 LSCC 反馈列表的关系

### 8.1 替换补偿计算，而非重复补偿

新预测器已经回放全部在途命令和渐进执行。因此不能在其计算结果上再加原 LSCC 的 $\sum R_a$，否则同一批命令会被补偿两遍。

实现上仍保留有序命令历史，但将“按固定时延移出 FIFO 即认为目标效果已兑现”的计算，替换成“按时间轴预测其实际到达影响”。命令登记记录与实际发送记录是两种不同证据。

### 8.2 理想条件下与原式的一致性

下面只说明代数一致性，不是一般稳定性证明。设服务恒为 $C$、队列在整个预测区间内非空、不触发限幅或裕量、$d_0=0$，命令在源端立即执行，且 $L=NT$、$T_c=T$。则：

$$
q_{k+N+1}=q_k+T\sum_{j=1}^{N}u_{k-j}+Tu_k-(N+1)CT.
$$

令终点等于 $q_{\mathrm{ref}}$，可得：

$$
u_k=C-\frac{q_k-q_{\mathrm{ref}}}{T}
       +\sum_{j=1}^{N}(C-u_{k-j}).
$$

恒定服务下 $R_{a,k-j}=C-u_{k-j}$，这与 LSCC 式(2)的相应特例一致。服务随时间变化、队列为空、执行渐进、反馈丢失或发生限幅时，不宣称与原算法严格等价。

这条关系说明本方案的落点：保留原来对未生效控制的考虑，扩展其中的执行描述，而非无依据另加一项累计偏差。

## 9 状态切换与异常处理

| 状态 | 进入条件 | 行为 |
|---|---|---|
| 初始化 | 无足够执行样本 | 用基线参数与保守执行模型；同时记账，不宣称已获执行补偿收益 |
| 正常补偿 | 时间对齐、样本新鲜、模型误差可接受 | 执行模型预测、标量目标选择、慢速更新参数 |
| 低置信度 | 摘要老化、模型失配、需求变化可疑 | 保留已知目标历史，扩大经验裕量，限制增速；使用固定保守参数和有界探测 |
| 紧急减速 | 实测高水位或服务明显下降 | 发送最低目标，保留原有PFC/缓存保护；不承诺可挽回在途峰值 |
| 路径或计数会话变化 | epoch改变、计数不连续 | 停止旧模型更新，保留旧在途影响的保守估计，重新测量和初始化 |

摘要超时阈值以发送周期和正常传播分布为基础，不能小于正常跨域时延。初版可取“正常报告到达间隔上界加若干丢失周期”，通过测试确定，不写死为微秒级。

低置信度持续时回到预先定义的基线补偿模式。切换应从当前实测队列和完整命令历史重建状态，过渡期只允许受限变化，不能清空反馈历史导致突然放量。该回退是兼容性措施，不证明回退模式在所有扰动下安全。

迟到摘要可以用于尚保留的历史对账，但不能覆盖新的命令。摘要有洞时按实际缺口标记未知；重复报文通过 report_seq 与累计计数去重。服务暂停时允许预计服务为零，不能为了避免除零人为给它一个看似可用的正带宽。

## 10 端到端执行流程

### 10.1 发送侧 DCI

```text
收到命令：
    检查 group、epoch、序号和有效期
    在下一桶边界登记最新有效目标，记录登记时间
    更新伪队列排空速率；不清空伪队列，不额外重复处罚

转发数据：
    沿用原 LSCC 的流表、伪队列和 direct CNP 逻辑
    在数据真正离开长链路出口时累计 X

每个 δ：
    封存实际字节 Xj、目标积分 Uj、登记版本和执行辅助状态
    下一桶重新计数

每个 Ts 或受限的事件触发：
    发送可去重的执行摘要；无数据时仍维持心跳
```

### 10.2 接收侧 DCI

```text
收到摘要：
    校验会话、序号与计数连续性
    对齐目标登记、实际发送与到达记录
    标记已确认、未知和时间分辨率不足的区间
    只在可信样本上更新执行参数；不把历史偏差加到当前队列

每个 T：
    采样真实 q、同口径到达与出队、服务/暂停状态
    固定本轮执行参数、服务预测、时延和经验裕量
    从最新执行观测回放到当前，再构建未来命令轨迹
    以真实 q 为初值，对候选 u 预测到 L+Tc
    检查整个时域峰值及终点，选择最大可行目标
    无可行目标或实测紧急时，执行明确的减速/降级分支
    分配新 command_id，发出并保留命令历史
```

每轮只发送一个聚合目标。模型拟合与参数更新比目标计算更慢；报告的到达不会每次额外触发一次独立乘性降速。

## 11 参数与部署代价

### 11.1 第一轮实验起点

下表用于复现实验起步，不是通用最优配置。

| 参数 | 起点或选择原则 |
|---|---|
| $T$ | 先沿用 LSCC 的200 μs，随后与基线同范围扫描 |
| $\delta$ | 先取25 μs，检查更细与更粗时间桶的误差/成本 |
| $T_s$ | 先等于T，再扫描0.5T、2T、4T |
| $d_b,d_f,d_0$ | 分别测量，初版不假设往返对称；记录误差 |
| $T_c$ | 不小于T；参考可信阶跃响应的收敛时长并设上限 |
| $g_\uparrow,g_\downarrow$ | 离线校准初始化，分方向有限历史更新 |
| $q_{\mathrm{ref}}$、物理缓冲 | 与基线一致；若改变必须单独消融 |
| $E$、步长范围 | 在独立校准负载选定，测试负载不按答案调参 |

一阶模型下，剩余偏差缩小至10%约需 $\delta\ln(0.1)/\ln(1-g)$；$g=1$ 时按一个桶计。该量仅辅助选取 $T_c$，不能当作真实 DCQCN 的收敛保证。为避免方向切换造成时域抖动，首版以两个可信方向中较慢者确定一个固定时域，每个模型更新周期才调整一次。

### 11.2 状态与计算不能忽略

新增聚合状态的数量约为 $O(GH_{\mathrm{hist}}/\delta)$，外加命令历史和执行参数。$G$ 是控制对象数，$H_{\mathrm{hist}}$ 至少覆盖报告年龄、控制传播、执行回放和允许的乱序窗口。

例如历史窗口4 ms、桶宽25 μs，共160桶；若内部桶记录压缩为32 B，单对象约5 KiB桶状态，64对象约320 KiB，尚未计命令、索引和原 LSCC 流表。这是设计估算，不是 ASIC 实测。

若某种汇总格式的负载为96 B、每200 μs发一次，单对象约3.84 Mbit/s，64对象约245.76 Mbit/s，未计链路封装。若携带8个细桶，报文通常更大，必须按实际格式重算，不能沿用96 B的开销。应比较分组汇总、增量编码和只用接收侧计数的方案。

标量求解虽简单，也不是免费：3 ms时域、25 μs桶宽共有120步，8轮二分加两个端点检查，最多约1200次桶演算/对象/更新；64对象、每200 μs更新时约3.84亿次桶演算每秒。实现应缓存与当前候选无关的前缀，限制控制对象数，测量真实处理时延。首版优先 DPDK/软件原型，不据此宣称可在每包 ASIC 流水线中完成。

### 11.3 主机改动边界

首版沿用 LSCC 的 direct CNP/DCQCN 执行接口，不要求主机新增 $R/N$、信用或外部逐流速率表。获取精确应用需求可能需要主机配合，因此不作为首版必需输入；相应地，需求受限只能保守处理。

发送字节计数、控制报文和时间戳仍需 DCI 实现。P4 能计数不意味着能方便访问全部 MMU 状态或完成预测器；数据面采样与软件控制协同时，读数和命令下发延迟也要进入实际时间轴。

## 12 如何证明这个方案值得做

### 12.1 先证明动机，不先追求更好的FCT曲线

首先在原 LSCC 中同时记录目标速率、实际发送速率、伪队列、真实队列和命令登记时间。证明执行偏差在性能退化之前出现，并且在控制其他变量后仍有解释力。

分别改变执行响应和下游服务，不能只看总队列残差。若性能差主要来自不可预测服务变化，而执行误差很小，则本方案选错了主因。

### 12.2 必须设置的基线

| 基线或消融 | 回答的问题 |
|---|---|
| 原LSCC复现 | 基本实现是否符合论文 |
| 充分调参的LSCC | 是否只是原T、ΔR设置不合适 |
| LSCC加固定非对称步长 | 是否只需加速慢、减速快 |
| LSCC加实测自适应步长，不改预测器 | 执行模型是否比简单调参更有价值 |
| 新预测器但使用理想即时执行 | 收益是否来自队列预测重写，而非执行校准 |
| 新预测器只使用接收侧到达计数 | 发送摘要是否提供独立信息 |
| 完整v0.4，但固定执行参数 | 在线更新是否真的有必要 |
| 完整v0.4 | 评估最终组合 |
| 理想已知执行模型 | 衡量估计损失；不能偷看未来需求和服务 |
| 简单聚合整形 | 固定容量场景是否存在更简单替代；计入源侧排队 |

所有比较保持相同缓冲、PFC配置、普通/direct CNP配置、初始流速率和测量口径。共同的紧急保护在相关基线同样启用。参数在校准集确定，报告测试集与敏感性，不逐条负载选择最优参数。

### 12.3 场景与观察量

| 场景 | 主要目的 |
|---|---|
| 固定服务、流批量加入与退出 | 隔离执行能力变化 |
| 源侧短时拥塞后恢复 | 观察发送低于目标及恢复过冲 |
| 应用受限后突然恢复 | 检查负偏差是否被误当成可补发额度 |
| 远端服务下降后恢复 | 检查是否混淆执行误差与服务误差 |
| 不同本地RTT、不同源端CC状态 | 检查固定T/ΔR条件的适用范围 |
| 摘要丢失、乱序、延迟与时钟偏差 | 检查对齐、降级与恢复 |
| 持续执行饱和或暂停 | 检查最低目标、无可行预测与恢复探测 |

第一阶段固定长链路路径，先做单聚合对象的流体/离散事件模型，再进入真实 DCQCN 的包级仿真。聚合执行模型只能检验算法逻辑，不能给出真实 RDMA 的FCT或公平性结论。

核心指标包括：同时间口径的发送预测误差、目标跟踪误差、真实队列峰值与面积、源侧真实队列、goodput、恢复时间、PFC次数/持续时间、短长流FCT和公平性。两侧排队都必须计入，防止仅把队列搬到发送侧。

评价时比较“相近goodput下的队列与FCT”以及“相近队列约束下的goodput”，避免通过一味保守制造表面收益。报告多随机种子及置信区间；对确定性阶跃单独展示完整时间序列。

### 12.4 停止深化的条件

如果经过调参的LSCC已经使执行偏差很小，或简单自适应步长取得相同收益，就应收敛为更轻的参数机制。若接收侧计数与目标历史足够，删除发送细摘要。若一阶模型频繁失效，先判断是否值得提高状态维度，而不是自动叠加复杂学习器。

若只有掌握真实未来需求/服务的理想模型才有效，说明实际可用信息不足，不能把这种结果当成方案可行性证据。

## 13 理论分析与创新边界

第8节只证明一组理想条件下的代数一致性。完整系统仍包含传播时延、采样、执行动态、队列非线性、目标限幅、普通CNP和模型更新，不能从标量求解的单调性推出闭环稳定。

建议先固定执行参数与服务、在线性工作区建立离散闭环，考察不同延迟、增益失配与更新周期下的特征根；再加入饱和、空队列和模型切换。最后才讨论分方向增益更新与降级逻辑。已有Smith预测控制的鲁棒稳定性结果可作为方法参考，但其假设不能直接移植为本方案定理。[2]

候选贡献是：在LSCC现有执行接口上，将按反馈目标推算的补偿改成由实际发送校准的执行轨迹补偿，并用有明确时间语义的账本避免重复补偿与虚假欠发送恢复。

目前尚未完成全面查新。预测控制、执行器失配、自适应步长和反馈序号都不是单独的新概念；需与LSCC后续改进、网络化控制和其他DCI方案系统比较。BiCC/ATC的目的调度与长链路窗口不并入主线，避免把多个独立研究问题混成一个方案。[3—4]

## 14 本版结论

v0.4把问题从“能否镜像远端队列”收敛为“LSCC能否准确判断其控制输入在源端产生的实际结果”。接收侧使用真实队列，发送侧记录实际注入，版本和时间戳负责对齐；执行模型只覆盖尚未观测的部分，并随证据不足而收缩。

下一步最重要的证据是：真实LSCC执行路径中的目标—发送失配确实造成了可观性能损失，而且增加执行轨迹补偿比充分调参和简单自适应步长更有效。在此之前，本版是完整的候选研究设计，不是已经验证的拥塞控制算法。

## 附录 A 本版可先验证的逻辑性质

以下性质只适用于本文定义的账本与简化预测器，不能替代网络实验。

1. 字节积分：目标在桶内变化时，分段目标积分与实际字节之差应守恒，不能用桶末目标覆盖整桶。
2. 历史去重：同一个累计计数摘要被重复接收，不应改变已确认的字节总量；缺失细桶不能伪造为已观测细节。
3. 非负截断：先空闲再突发时，预测不能把先前空闲服务用于抵消后来的排队。
4. 单调求解：固定执行参数和外生服务预测时，候选目标增大不应降低预测队列。
5. 理想退化：恒定服务、非空队列、即时执行和无约束条件下，第8节闭式解应使预测终点等于参考队列。
6. 时间因果：候选命令不能改变其最早起效时刻之前的到达和队列。
7. 实测锚定：历史偏差抵达后，只通过真实队列与模型校准影响控制，不再另外加到当前队列。
