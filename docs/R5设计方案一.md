# R5 设计方案：基于实际发送历史与远端队列预测的跨域注入控制

R5 基于端侧 DCQCN，在跨域链路两端设置 DCI 网关。近端网关 A 记录实际发送、预测远端队列并逐流整形；远端网关 B 测量队列和服务状态并反馈。方案希望在长反馈时延下提高可用带宽利用率，同时控制远端排队和近端缓存压力。吞吐、完成时间和稳定性收益属于待验证的研究目标。

本文说明方案的原理、工作过程和适用边界。源码结构、状态字段、消息格式和实现步骤见 [R5 代码设计与实现](R5代码设计与实现.md)。

<a id="r5-s1"></a>
## 1. 研究背景与目标

跨域 RDMA 的控制反馈需要经过长距离传播。当 A 收到 B 的队列报告时，报告已经滞后：报告采样之后，部分数据已经到达 B，另一些数据仍在 WAN 中。仅按报告中的旧队列调速，容易在拥塞已经形成后继续注入，或在队列已经排空后继续限制发送。

另一方面，整形目标不等于实际发送。主机可能因 DCQCN 降速而供给不足，A 也可能因调度或 PFC 暂停而没有发出数据。用配置速率推算在途量，会把这些没有发出的字节当作未来到达。

R5 围绕以下三个核心问题展开设计：

1. 如何结合 B 的滞后观测与 A 的实际发送历史，估计当前及控制动作生效时刻的远端队列，减少对在途数据及其排队影响的误判？
2. 如何预测当前控制动作对一个 A–B RTT 之后远端队列的影响，在检查预测窗口内队列峰值与缓存风险的基础上，更及时地利用可用容量？
3. 如何在保留主机 DCQCN、原生 CNP 和 PFC 的条件下，协调 A 的跨域注入与本地反压，使输入速率与实际转发能力相匹配，缓解本地积压并避免过度反压？

评价需要同时考虑吞吐、接收 goodput、完成时间、A/B 排队、PFC、丢包、反馈与状态开销。仅把积压从 B 移到 A，或仅让速率曲线更平稳，不足以说明方案改善了传输性能。

<a id="r5-s2"></a>
## 2. 基本假设与整体架构

基本场景是一条受管理的 A—B 路径，由一个 A 统一管理相关跨域流。网关可以识别报文、查询本地转发出口、测量本地入队与出队，并通过真实网络路径交换控制信息。链路容量、MTU、对端控制通道和有限资源池可以配置；未来流身份、大小、启动时间和结束时间不能预先提供给控制器。

预测需要可对应的两端时间戳，以及有来源说明的正向和反向时延。固定路径、无损、时延变化较小是基础模型的分析条件；丢包、重传、重路由和时延变化必须显式记录，不能继续假定每次 A 发送都按原时刻到达 B。

```mermaid
flowchart LR
    H["发送主机：DCQCN"] --> A["A：动态建表、预测、逐流整形"]
    A --> W["WAN：实际在途数据"]
    W --> B["B：动态建表、测量、正常转发"]
    B --> D["目的端网络与接收主机"]
    B -. "逐流与资源状态反馈" .-> A
    A -. "本地缓存反压 CNP" .-> H
    D -. "原生 CNP 透传" .-> H
```

| 控制作用 | 依据 | 动作及其边界 |
|---|---|---|
| A 跨域注入控制 | B 的历史观测、A 实际发送、本地供给、共享预算 | 预测并执行逐流发送上限；动作经正向传播后影响 B |
| A 本地反压 | 本地积压、输入输出差额、剩余缓存 | 向造成压力的发送端 QP 发 CNP，调节 A 的输入 |
| B 测量与转发 | 本地队列、出队、调度和暂停 | 正常服务并反馈，不因自己的队列升高而额外压低同一队列的服务 |
| 主机 DCQCN | 原生端到端拥塞信号及近端 CNP | 调节主机供给；网关不能强迫主机持续提供目标速率 |
| PFC | 实际优先级队列的缓存压力 | 限制对应优先级的发送资格，可能同时暂停多条流 |

B 的独立下游主动限速不属于基本方案。若以后引入，其职责只能是保护 B 后方的拥塞点，且必须将其造成的服务变化反馈给 A。看到原生 CNP 本身不能证明拥塞位于 B 后方。

## 3. 逐流对象、共享资源与变量

### 3.1 流身份与优先级

基础控制对象是一条有向 RC QP 连接的数据流。统一使用以下三个报文字段识别：

$$
\mathrm{FlowKey}_f=(\mathrm{Src\ IP},\mathrm{Dst\ IP},\mathrm{BTH.DestQP}).
$$

两个 DC 使用互不重叠的主机地址，各 DC 内每个接入 Leaf 分配一个独立的 `/24` 主机子网。同一 Leaf 下的主机属于同一子网，不同 Leaf 的子网不同；每台主机的 RDMA 地址就是其唯一的非回环接口 IP。基础场景限定为主机单接入，不支持地址重叠或路径中的地址转换，因此 FlowKey 不包含网络命名空间。目的 QPN 取自 BTH 的 `DestQP` 字段；UDP 端口与 PG 均不参与流身份匹配。UDP 源端口仍可用于 ECMP，不能直接等同于真实 QP 身份。[NVIDIA RoCE 文档](https://networking-docs.nvidia.com/doca/archive/3-5-0/rdma-over-converged-ethernet)、[NVIDIA 报文格式说明](https://docs.nvidia.com/holoscan/sensor-bridge/fpga-ip/dataplane)。

相同源、目的 IP 下，不同目的 QPN 对应不同流；相同三元组不会因 UDP 端口或 PG 变化而成为另一条流。PG 变化仍须重新检查队列、暂停和资源关联。QPN 重用与迟到报文按第 9 节的生命周期规则处理。地址分配与报文适配的具体设计见 [实现文档第 4 节](R5代码设计与实现.md#impl-s4)。

A 为每条流独立维护实际发送历史、预测、候选上限和整形状态。B 为实际到达的流维护驻留和转发计数。B 的逐流计数不要求每流一个物理 FIFO，也不表示 B 已提供逐流公平排队。

PG 是 PFC 和调度属性，不是 R5 控制组身份。不同 PG 可以竞争同一个物理出口；同一 PG 内的不同流仍有独立控制状态。暂停影响按实际优先级传播，逐流整形无法消除共享优先级的共同暂停。

### 3.2 重叠的共享资源

每条流可以同时关联多个资源，资源集合允许交叉。

| 资源 | 约束 |
|---|---|
| A 的 WAN 出口 $a$ | 经过该物理出口的总发送能力 |
| B 的实际出口 $p$ | 共享出口的可用服务和缓存风险 |
| 目的接收资源 $d$ | 跨不同 B 出口、最终汇聚到同一接收接口或接入瓶颈的总预算 |
| B 的排队资源 $e$ | 实际队列及对应服务；按真实调度和 PFC 属性建模 |
| 共享缓存池 | 同一时刻真实驻留字节的总上限 |

对相应流集合 $\mathcal F_a,\mathcal F_p,\mathcal F_d$：

$$
\sum_{f\in\mathcal F_a}r_f\le C_a,\qquad
\sum_{f\in\mathcal F_p}r_f\le C_p^{\mathrm{available}},\qquad
\sum_{f\in\mathcal F_d}r_f\le C_d^{\mathrm{budget}}.
$$

B 出口和目的资源预算应扣除其他业务或其他入口已经占用的份额。例如，三条流经过两个 B 出口汇聚到一个 100 Gb/s 接口，仍共同受该接口预算约束，不能分别从两个出口领取完整的接收能力。

目的预算必须有可信来源。已知接入容量可以提供物理上限；竞争条件下的可用份额需要接收端、目的 ToR 或管理平面信息。B 按目的 IP 汇总出队量，不能测出下游接收接口的可用带宽。信息未知时保持未知，也不能把目的主机与目的 ToR 的容量混用。

### 3.3 统一符号与计量

| 符号 | 含义 | 单位 |
|---|---|---|
| $q_f^A(t),q_f^B(u)$ | 流在 A、B 的队列驻留量 | 字节 |
| $X_f(v)$ | A 截至 $v$ 实际向 WAN 发出的累计字节 | 字节 |
| $r_f^{\mathrm{cap}},r_f$ | 预测允许的候选上限、本轮实际分配的整形速率 | 字节/秒 |
| $K_f,z_f(t)$ | 逐流令牌桶容量、当前余额 | 字节 |
| $\widehat x_f(v\mid t,\mathbf r)$ | 候选计划下预计实际发出的速率 | 字节/秒 |
| $\widehat\mu_f(u)$ | B 按实际调度可分给流的预测服务 | 字节/秒 |
| $Q_e(u)$ | B 排队资源的总队列，包括受控流和背景流量 | 字节 |
| $b_e,c_e,y_e$ | 背景到达、持续积压时可获得的总服务、实际出队速率 | 字节/秒 |
| $q_f^\star,Q_e^\star$ | 逐流目标驻留量、共享资源目标队列 | 字节 |
| $d_f,d_b,T=d_f+d_b$ | 正向时延、反向反馈时延、A–B 参考 RTT | 秒 |
| $s,t,F=t+T$ | B 采样时刻、A 决策时刻、预测终点 | 秒 |
| $\delta_a,h=t+\delta_a+d_f$ | 本地动作延迟、新动作影响 B 的起点 | 秒 |
| $L=T-\delta_a-d_f$ | 新动作能影响预测终点的时长 | 秒 |

队列、令牌、累计发送和容量使用同一完整报文字节口径。接收端有效载荷 goodput 另行统计。链路容量、可用服务和实测出队量是三个不同量：

$$
\text{物理端口容量}\neq c_e(u)\neq y_e(u).
$$

共享队列满足 $Q_e=\sum_{f\in e}q_f^B+Q_e^{\mathrm{other}}$。总量模型加入背景到达后减总服务；逐流模型减已经分配给该流的服务，不能再扣一次背景竞争。待处理缓存等其他驻留位置也要进入实际缓存总账。

## 4. 首包发现、反馈与启动

### 4.1 两端独立发现

初始化时，A、B 的逐流控制表为空，仅配置网络信息、控制参数和有限资源。实验流列表用于安排应用发送与事后统计，不进入网关决策。

“首包”是本地首次观察到且没有有效记录的数据报文，不要求知道应用真正的第一包。

1. A 从实际报文字段取得 FlowKey，查表未命中时申请状态和调度资源，关联自己的出口与流量类别。
2. A 成功建表时赋予四帧满桶，并在下一次 5 μs 控制周期按本地出口及已知目的容量参与带宽分配；额外等待最多约一个控制周期，不等待 B 状态或查询握手。当前首包仍经过准入、扣令牌和真实发送记账。
3. 数据实际到达 B 后，B 独立建表，用本地转发结果确定出口和队列，计入首包的准入、出队或丢弃。
4. B 首包入队后主动反馈流状态及相关资源观测，并持续周期反馈；A 收到有效反馈后直接关联已有流表，在下一控制周期进入预测调速。

A 不能预先创建 B 状态，也不能预演每条未来流的完整路径。ACK、CNP 和状态反馈查表未命中时不创建数据流。

### 4.2 B 反馈什么

反馈包括流身份与控制代际、实际出口和队列、采样时间和顺序、逐流驻留与累计计数，以及共享资源的队列、服务、暂停和真实缓存约束。共享资源信息可以批量发送，避免为每流重复携带。

计数区分成功入队、实际出队、入队前丢弃、入队后丢弃和重传。累计计数用于守恒核对和校正，不天然代表未来服务。

A、B 为本地记录分配各自的控制代际 $g_A,g_B$。B 主动发送状态，A 按对端会话、FlowKey 和 B 代际关联已有本地记录，不进行 QUERY/REPLY 握手。首份状态采样不得早于 A 本地建表；后续还须通过代际、序号、年龄、资源和累计计数检查。当前实现保留会话内的流身份且 RNIC 不重用 QPN；完全回收、同键重用或会话重启需要另外解决跨代迟到反馈，不能据此假定已经支持。

B 即使没有新数据，也应继续提供必要的暂停、恢复和资源状态，避免出现“停发后没有反馈、没有反馈就无法恢复”的停滞。

### 4.3 远端尚未知时如何发送

首份有效反馈之前，A 保留实际发送历史，把 B 队列、出口和服务标为未知，不能假设 B 已报告空队列。

| 状态 | 启动策略 |
|---|---|
| 有新鲜且确实适用的资源信息 | 在相关预算内参与分配；不复制另一条流的 B 出口或专属服务份额 |
| 远端状态或出口未知 | 每流候选速率取 A 物理出口容量，经所有活动流的共享出口及已知目的容量约束分配；按所得最大可用份额发送，不设置 1% 探测速率 |
| 已知暂停、缓存风险或本地资源不足 | 保留桶余额，暂缓发送许可，条件恢复后重新检查 |

启动额度沿用每流四帧令牌桶，按分配速率连续补充，并非只能发送四帧后等待 B 授权。所有流的分配总速率受 A 物理出口和已知目的容量约束，实际发送由物理端口串行化；不新增共享低速启动许可。B 状态未知时无法保证远端无积压，多流同步启动的排队风险需实测。已收到但过期或缺失必要历史的反馈仍按保守保护规则处理，不能退回高速启动绕过保护。

首包发现不说明流最终有多长。短流可能在首份反馈前完成，其收益来自合理启动和较低排队，不能预先知道短流身份后特殊放行。

## 5. B 服务能力的估计

B 在相邻采样时刻 $s_{k-1},s_k$ 之间实际出队 $\Delta D_e$ 字节，则：

$$
\overline y_{e,k}=\frac{\Delta D_e}{s_k-s_{k-1}}.
$$

该值能否用于估计服务，取决于这段时间是否有数据可发、是否暂停以及调度条件是否变化。

| 观测条件 | 处理 |
|---|---|
| 独占出口、无暂停且约束已知 | 使用有效物理容量，不因供给少而降低容量估计 |
| 共享服务，区间持续积压、未暂停且无已知状态变化 | 用区间实际出队更新近期服务估计 |
| 区间曾排空，且没有新限制 | 保留最近有效估计，仍受容量和调度上限约束 |
| 当前暂停或服务受限 | 约束受影响流和队列；完全暂停的模型区间内服务为零 |
| 恢复、路径改变或没有有效估计 | 独占服务按已知容量恢复；共享服务参考仍适用的历史值并等待新观测，缺少依据时受限启动 |

持续积压要求区间内没有排空，不能只看两个端点都非零。历史平均出队与采样时刻的暂停状态应分别表达。把当前暂停或服务值延续到未来是模型假设，不是预知其未来持续时间。

单流服务 $\widehat\mu_f$ 必须服从 B 的实际调度。不能给每流完整端口容量，也不能因为 A 公平分配了速率，就假定 B 的 PG FIFO 具有相同的逐流公平性。具体分摊估计仍需要明确策略；估计不足时，单流结果应标为近似，共享物理队列风险必须独立检查。

<a id="r5-s6"></a>
## 6. 当前决策时刻之后一个 RTT 的队列预测

### 6.1 时间轴

A 在 $t$ 决策，最新 B 状态采样于 $s$，预测目标为：

$$
F=t+T,\qquad T=d_f+d_b.
$$

忽略本地动作延迟时，新动作从 $h=t+d_f$ 开始影响 B。从旧采样到目标的总跨度为：

$$
H=F-s=(t-s)+T.
$$

对称且反馈及时的路径中，$t-s\approx T/2$，因此从旧观测到终点约跨越 $1.5T$；这与“从当前时刻向前预测一个 RTT”并不矛盾。反馈更旧时按真实样本年龄计算。

例如单向时延为 5 ms，A 在 20 ms 决策，B 最新采样为 15 ms，目标是 30 ms：

| B 时间段 | 对应 A 发送时间 | 决策时已知程度 |
|---|---|---|
| 15–20 ms | 10–15 ms | 实际发送历史 |
| 20–25 ms | 15–20 ms | 实际发送历史，含在途数据 |
| 25–30 ms | 20–25 ms | 候选未来发送计划 |

因此未来发送计划只延伸到 $F-d_f=t+d_b$。A 在 25–30 ms 发送的字节不能提前放进 B 的 30 ms 队列。

若本地动作延迟为 $\delta_a$，则 $h=t+\delta_a+d_f$，$[t,t+\delta_a]$ 按此前已承诺动作估计，不能当作已发生历史。新动作的有效时间为 $L=T-\delta_a-d_f$；$L\le0$ 时，该终点对新动作不可控。

### 6.2 实际历史与候选未来轨迹

定义候选速率向量 $\mathbf r$ 下的累计发送：

$$
\widetilde X_f(v\mid t,\mathbf r)=
\begin{cases}
X_f(v),&v\le t,\\[4pt]
X_f(t)+\displaystyle\int_t^v\widehat x_f(w\mid t,\mathbf r)\,dw,&v>t.
\end{cases}
$$

历史段只用成功 WAN 发送的完整包字节计数，不使用应用 payload 或目标速率。每包只累加累计 TX；新流建立时保存零计数起点，随后每 5 μs 保存累计快照。快照与完整预测、速率分配共用控制周期，不从新流首包即时执行完整决策。

相邻快照 $S(t_{k-1}),S(t_k)$ 的差值是该区间成功发送量，以 $r_k=[S(t_k)-S(t_{k-1})]/(t_k-t_{k-1})$ 均匀重放。上式中的历史 $X_f(v)$ 在区间内部采用累计快照的线性插值，只有快照端点的累计值是精确计数。每个区间使用结束快照时的探测时延基值加最大数据帧串行化时间映射到 B，并固定该映射；后续探测不重映射旧区间。采样位于区间内部时只计算重叠部分，共享资源合并所有流的区间速率后统一扣服务、截零。共享池按共同的区间边界及未来包事件计算各队列之和的峰值。

这是周期平均近似，丢失 5 μs 内的突发和包长差异，不能宣称与逐包预测等价或由此保证不丢包。需分别报告终点误差与峰值低估。

未来段先采用恒定候选速率，每个短控制周期重新规划，但预计发送 $\widehat x_f$ 仍受供给、令牌、共享出口和暂停限制。

设 $\widehat H_f(t,v)$ 是依据近期入口观测估计的主机到达字节，则对每个未来时刻：

$$
\widehat{TX}_f(t,v)=\int_t^v\widehat x_f(w\mid t,\mathbf r)\,dw
\le q_f^A(t)+\widehat H_f(t,v),
$$

$$
\widehat{TX}_f(t,v)\le z_f(t)+\int_t^v r_f(w)\,dw.
$$

第二式只是必要包络。桶满后的补充会溢出，零速率即使有余额也不发包；不能用窗口末尾的总量取小代替分段发送。后半段才到达 A 的数据，也不能被提前发出。

正常轨迹使用供给估计；缓存风险检查还应考虑候选速率、物理出口和突发额度允许的较高到达轨迹，避免因当前供给少而放开过大的上限。预测输入不包括未来应用列表。

### 6.3 推进单流驻留与共享队列

在固定、无损路径的基础模型下：

$$
\Delta\widehat A_{f,k}
=\widetilde X_f(u_{k+1}-d_f\mid t,\mathbf r)
-\widetilde X_f(u_k-d_f\mid t,\mathbf r).
$$

从 $\widehat q_f^B(s)=q_f^B(s)$ 出发：

$$
\widehat q_f^B(u_{k+1})
=\widehat q_f^B(u_k)+\Delta\widehat A_{f,k}-\Delta\widehat D_{f,k},
\qquad
0\le\Delta\widehat D_{f,k}\le\widehat q_f^B(u_k)+\Delta\widehat A_{f,k}.
$$

$\Delta\widehat D_{f,k}$ 由实际调度、暂停和服务分摊约束。共享队列可写为：

$$
\widehat Q_e(u_{k+1})=
\left[\widehat Q_e(u_k)+\sum_{f\in e}\Delta\widehat A_{f,k}
+\widehat b_e(u_k)\Delta_k-\widehat c_e(u_k)\Delta_k\right]^+,
\quad \Delta_k=u_{k+1}-u_k.
$$

其中 $[z]^+=\max(z,0)$。应在到达、排空、暂停和服务变化处切分，不能让早先闲置的服务抵消后来到达的数据。逐流服务之和与总量模型必须一致。

新反馈先校正其采样时刻，再重放至当前和终点。同一时间戳内的事件边界要由一致计数或事件顺序区分，避免重复计算。已知实际到达仍不等于知道采样后的真实队列，因为服务和背景流量还可能变化。预测应明确为条件量：

$$
\boxed{\widehat q_f^B(t+T\mid t,\mathbf r)}.
$$

### 6.4 峰值保护与预测校验

终点用于评价动作，缓存保护检查整个未来窗口：

$$
\widehat Q_{e,\mathrm{peak}}(t\mid\mathbf r)
=\max_{u\in[t,t+T]}\widehat Q_e(u\mid t,\mathbf r).
$$

例如队列先到 20 MB、终点回落到 5 MB，而可用缓存只有 10 MB，该计划仍不可接受。多个队列共用缓存时，核算同一时刻的总驻留；不同资源视图不能重复计算同一批字节。

当前降速无法撤回已经发出的在途数据。即使新速率为零，动作生效前的到达仍保留，保护只能避免继续增加风险。

每次决策冻结起点、服务假设、余额、发送资格、计划与结果，分别保存：

- **原始条件预测**：与同一时刻的后续 B 实测比较，同时记录计划和实际发送的差异。
- **实际输入重放**：保留原服务模型，用后来发生的真实发送替换未来计划，辅助定位模型误差。

后者不能替换前者，也不代表在线预测已经准确。滚动改速率引起的计划差异不能直接算作持续模型失准。$F$ 的观测通常在 $F+d_b$ 之后返回；采样不对齐或历史缺失时标记不可校验。

## 7. 候选动作、资源分配与精确整形

### 7.1 候选上限与实际份额分离

忽略本地动作延迟，先重放得到：

$$
q_{f,h}=\widehat q_f^B(t+d_f\mid t),\qquad L=T-d_f=d_b.
$$

在供给充足、忽略桶内突发、单流服务和候选实际发送近似恒定的流体模型中：

$$
\widehat q_f^B(t+T\mid t,r_f)
=\left[q_{f,h}+(r_f-\mu_f)L\right]^+.
$$

面向目标驻留 $q_f^\star$ 的初始候选为：

$$
\boxed{r_f^{(0)}=\left[\widehat\mu_f+\frac{q_f^\star-q_{f,h}}{L}\right]^+}.
$$

分母是动作能影响终点的时长，不是整个 RTT。有执行延迟时采用对应的 $h,L$。未知 B 状态时使用第 4.3 节的启动分配规则，不套用此式。

候选经物理约束和风险检查形成 $r_f^{\mathrm{cap}}$，再分配本轮速率 $r_f$。队列为空导致的 $r_f=0$ 不能写回为不可恢复的候选上限。$q_f^\star$ 应从共享目标 $Q_e^\star$ 中分配，不能每新增一条流就复制一份队列目标或整机缓存。

### 7.2 分配与滚动执行

默认流权重相同，进行最大最小公平分配：逐步增加活动流份额；流达到候选上限时冻结，某资源用尽时冻结继续增长会消耗该资源的流，其余流继续使用剩余预算。

每轮顺序是：

1. 反馈到达时校验并保存观测；每 5 μs 先保存累计 TX 快照、回收过期历史及更新统计，再统一重放历史、校验冻结预测和计算必要的此前承诺动作。PFC 与已经确认远端停服的立即停止不等待预测。
2. 形成逐流候选上限。
3. 联合满足 A 出口、B 出口及有来源的目的接收预算。
4. 按最终速率、真实余额、供给和发送资格生成未来发送轨迹。
5. 检查终点、完整窗口峰值及缓存池；必要时收紧相关上限，再分配并复核。
6. 执行下一短控制周期 $\Delta_c$，冻结预测，再滚动更新。

预算借用或分配改变后，预测也要对应实际执行动作。空队列不占固定份额，其他积压流可以使用闲置机会，但不能越过共享约束和预测上限。没有主机供给时，增加份额也不会凭空产生吞吐。

### 7.3 四帧满桶与零速率

整形使用按时间生成的速率型令牌，不是等待 B 或 ACK 归还额度的信用窗口。

$$
K_f=4\times\mathrm{frameBytes}_f,\qquad z_f(t_{\mathrm{create}})=K_f.
$$

帧长来自 MTU、协议和设备计量配置，不能把首个短包当作后续最大帧长。若计量帧长为 1048 字节，则桶容量和初始余额为 4192 字节；短包数量可能超过四个。

无发送且速率不变时：

$$
z_f(t+\Delta)=\min(K_f,z_f(t)+r_f\Delta).
$$

真实出队长度为 $\ell$ 的报文才扣减 $\ell$。切换速率前先按旧速率结算到当前时刻。

| 情况 | 规则 |
|---|---|
| 新建状态 | 完整满桶；立即分配正速率，仍受共享出口预算、PFC 和调度机会约束 |
| 正速率 | 按时间补充至容量上限，实际出队扣减 |
| 零速率 | 保留余额、不补充、停发 |
| 恢复正速率 | 沿用余额，不重填，不追补零速率期间额度 |
| PFC 暂停 | 不发送、不清零；若速率仍为正可补充至满，解除后的余额进入突发预测 |

多个满桶同时启动或恢复的总突发必须核算，并考虑物理端口串行化。已经计入实际发送历史的字节不能再作为未消费余额计算。

### 7.4 简化模型能说明什么

在固定且准确的服务、固定时延、充足供给、正队列、没有预算压低候选等理想条件下，令 $e(t)=q_f^B(t+d_f)-q_f^\star$：

$$
\dot e(t)=-\frac{e(t)}{L},\qquad
e_{k+1}=\left(1-\frac{\Delta_c}{L}\right)e_k.
$$

$0<\Delta_c/L<2$ 是这个简化离散模型的稳定条件，$0<\Delta_c/L\le1$ 对应不交替变号的收敛。它不是 DCQCN、PFC、共享调度和模型误差共同作用下的稳定性证明。

未饱和时，服务误差和生效点队列误差造成 $\Delta r=\varepsilon_\mu-\varepsilon_q/L$。扩大预测范围增加了可评估的动作影响，也增加了服务和供给假设，不能直接推出预测更准或吞吐更高。WAN BDP 描述在途量，不应直接作为 B 的目标队列。

## 8. 本地反压与端到端控制协作

近端 CNP 依据 A 的实际缓存压力，负责调节主机供给，不传递 B 队列误差或替代 A 的精确整形。

对同一实际缓存范围，设总队列 $Q_A$、输入 $\lambda_A$、输出 $x_A$：

$$
\dot Q_A=\lambda_A-x_A,\qquad
P_A=Q_A+[\lambda_A-x_A]^+\tau_{\mathrm{local}}+M_A.
$$

$\tau_{\mathrm{local}}$ 是从通知到输入变化可见的响应时间，$M_A$ 是突发余量；两者不能简单等同于传播 RTT。高低水位满足 $0\le Q_L<Q_H<B_A$。

| 情况 | 处理 |
|---|---|
| $Q_A\ge Q_H$ 且仍增长或基本不降；或净流入为正且 $P_A\ge Q_H$ | 向仍在输入且对压力有贡献的相关 QP 节制发送 CNP |
| 发出普通 CNP 后 | 对同一 QP 至少等待 $\tau_{\mathrm{local}}$ 再评价，避免重复响应尚未生效的通知 |
| 观察窗口内明确排空，且 $P_A<B_A$ | 停止追加普通 CNP，继续观察 |
| 压力持续或重新增长 | 满足发送间隔后再次通知 |
| $Q_A<Q_L$ 且没有新增风险 | 解除本轮反压 |
| $P_A\ge B_A$ 或明确耗尽风险 | 可提前结束普通等待，但仍遵守同一 QP 的最小通知间隔，必要时依靠局部流控 |

停止追加与解除反压不同。单个采样点的负增长不足以说明已安全；持续高位、缓慢排空也要观察。

A 必须能把主动 CNP 关联到发送端 QP。目的 QPN 不能一般性地替代源 QP；缺少可靠源端关联时，不能发送无法定位的主动通知。可用信息应来自报文、运行时连接管理或明确的协议协作，不能从实验流表预填。[THEMIS，§IV](https://zhangmenghao.github.io/papers/ICNP2025-Themis.pdf)。

原生 CNP 继续透传，既有 CE 保留。主机收到 CNP 后有自己的减速与恢复状态，不能假设每个 CNP 都造成一次固定幅度降速。[DCQCN，§3](https://conferences.sigcomm.org/sigcomm/2015/pdf/papers/p523.pdf)。

因此，同一次拥塞仍可能使 A 降低注入，同时使主机降低供给。B 恢复后主机可能仍低速。R5 的目标是减少不必要的本地追加反压，不承诺消除双重响应，也不以清除原生拥塞信息换取吞吐。

## 9. 动态生命周期与有限资源

### 9.1 空闲不等于连接结束

A、B 独立维护本地状态：

| 状态 | 保留与转换 |
|---|---|
| 活动 | 有积压、待处理报文或未完成数据操作；不得因长期暂停、零速率或没有新包而淘汰 |
| 空闲保留 | 本地排空后保留身份、余额、计数和必要历史；不长期占发送份额，再来包延续原状态 |
| 回收保护 | 连续空闲达到 $T_{\mathrm{idle}}$ 且旧账可安全处理后，释放重状态，保留身份、代际、余额和必要基线 |
| 无记录 | 保护期 $T_{\mathrm{guard}}$ 结束、无新数据和未完成引用后，释放身份槽位 |

周期反馈和控制定时器不刷新数据空闲计时。保护期内有数据则撤销回收、恢复原状态；重新排空后再开始计时。空逻辑队列可以先释放，但再次来包仍须重新取得队列资源。

A 的未核销在途量与 B 驻留必须由有效反馈、对齐计数或有依据的报文失效边界处理；不能因一个 RTT 已过就归零。无法核销时继续保留状态。冻结预测超过校验等待上限后记为无法校验，不为此无限保留历史。

若有覆盖排队、PFC 和允许重传的旧数据失效上界 $D_{\mathrm{old}}$，保护期至少覆盖 $D_{\mathrm{old}}+F_{\max}$ 和计时余量，$F_{\max}$ 为反馈最大可接受年龄。没有可靠上界时，有限超时不能证明此后绝无旧包。

### 9.2 迟到反馈与标识重用

反馈必须匹配当前控制会话、代际、样本顺序和有效期。无记录的反馈不建表，旧样本不使状态回退，计数重置后不能跨代相减。释放后复用槽位时，旧操作不能命中新对象。

控制代际不等于数据连接代际。没有可信连接代际时，相同 FlowKey 命中保留记录就按延续处理；不能凭序号跳变判定是新 QP。记录彻底删除后，只能将再次出现称为“重新发现的控制观测段”，按四帧满桶和启动分配规则重新接纳。

有限内存无法无限期记住所有旧连接，因此不能同时承诺同一真实 QP 终身只获得一次初始桶。若需要严格隔离旧包或禁止再次授信，必须有可信连接代际、可执行的标识复用隔离期或额外生命周期协作。

### 9.3 资源耗尽行为

流身份、逻辑队列、保护记录、历史、预测快照和等待缓存均有独立可核算的上限。保护记录空间从建表时预留；B 的逐流测量不要求每流物理队列。

资源申请失败时，先回收符合条件的空队列和到期记录，再进入有包数、字节数和等待期限的共享待处理区。资源释放后重试，保持同一流顺序。等待区满或超时则丢弃并记录原因，不能默认队列直通、合并控制身份或无限扩容。

已有积压流不因新流到来被驱逐。PFC 保护实际缓存，不能仅因流表满就无限暂停整个 PG。必要控制反馈和已有流排空要有有限资源保障。B 状态不足时反馈资源压力，A 限制相关未确认流的启动，并通过有界探测恢复。

在线发送历史改为按时间保留累计快照，记录数不再作为 WAN 出队资格。保留窗口覆盖反馈有效期、最大初始/允许探测时延、最大帧串行化时间及一个控制周期；回收时保留窗口边界前的一个快照，支持差分和插值。当前默认超时 20 ms、允许探测基值最多 20 ms，因此窗口约 40 ms 加串行化与 5 μs 边界余量，而非固定 25 ms。每流记录数量约为保留窗口除以 5 μs，再加边界记录；例如 25 ms 窗口约 5001 条。历史不再因待校验预测延长，预测所需样本超出覆盖范围时记为无法校验。

## 10. 代表性工作过程

**新流启动。** A 首次看到数据，成功申请状态后获得满桶，在下一次 5 μs 控制周期分配速率，再在出口与已知目的容量约束内发送；B 实际收到后独立测量并主动反馈。A 收到有效状态，用实际发送补足旧样本到当前的到达，再评价下一控制周期的动作。

**B 暂停与恢复。** B 报告受影响优先级的服务停止。A 停止相应注入、保留余额，模型仍计入已经在途的数据；A 缓存增长时才触发近端反压。B 恢复后报告有效服务，A 重新预测并分配，恢复的桶内突发也接受共享风险检查。

**主机供给下降。** A 的实际发送减少，历史段不会继续累计目标速率。空闲份额可分给其他积压流；原流恢复时重新竞争资源，不因之前分配为零而失去可恢复的候选上限。

**短暂空闲后继续发送。** 队列排空后保留状态，暂停份额但不清令牌；保留窗口内再来数据沿用原代际和余额。完全老化后再次发现则经过受限启动，不把缓存淘汰解释为已知连接结束。

## 11. 风险、适用边界与代价

若服务从 $\mu_0$ 降到 $\mu_1$，A 的动作经过总延迟 $D$ 才影响 B，在其他条件不变时：

$$
\Delta Q=(\mu_0-\mu_1)D,\qquad
B_e-Q_e(t_0)\ge(\mu_0-\mu_1)D+M_e.
$$

$D$ 包含采样等待、反向反馈、本地执行和正向传播。100 Gb/s 降为 50 Gb/s、响应需 2 ms 时，差额约为 12.5 MB。这是条件计算，不是实验结果。

峰值检查要求 $\widehat Q_{e,\mathrm{peak}}+M_e\le B_e$，并满足共享缓存池总约束。它只说明候选轨迹在模型假设和所选粒度下没有发现不足，不保证未知扰动、步内突发或窗口之后安全。预测不会缩短物理传播时间，也不能撤回在途数据。

反馈过旧、路径变化、服务未知或模型持续失准时，应降低相关上限或暂停，等待新状态；不能把没有拥塞反馈解释为容量充足。没有可靠误差边界时，这属于风险控制，不能声称任意扰动下零丢包。

其他主要边界是：

- 背景流量本身持续超过服务能力时，A 即使停发也无法独自稳定队列。
- 多 A 不能各自使用完整的 B 出口或目的预算；需份额配置或额外协调。
- A 的逐流公平不等于 B 的公平，也不等于不同主机、不同 QP 数量之间的全局公平。
- 逐流历史、关联确认和反馈有内存、带宽及处理开销；关联时延可能影响短流收益。
- DCQCN 造成的低供给、PG 共同暂停、源 QP 信息缺口和资源耗尽均可能限制收益。

严格信用窗口可以作为另一种有限缓存控制路线，但不属于本方案的速率令牌语义；多阶段动作优化、多入口协调和 B 下游独立限速也不作为基础能力。

## 12. 研究主张与评价依据

R5 的候选贡献是：在主机独立调速、网关可控注入的条件下，区分历史事实与未来动作，用实际发送和共享资源约束评价当前时刻一个 RTT 之后的队列，并刻画它与本地反压的性能边界。

需要证明的不是某个机制名称，而是在相同资源和可信信息条件下，吞吐、排队或完成时间是否得到可重复的改善。

| 主张 | 需要的证据 |
|---|---|
| 实际历史减少状态误判 | 旧队列、配置速率推算与实际历史重放在相同信息条件下的误差和低估尾部 |
| 完整 RTT 预测有效评价动作 | 时间移位正确，计划与执行可对应，终点和中途峰值均被检查 |
| 控制改善系统表现 | 主机 TX、A WAN 发送、B 出队、接收唯一有效字节及 A/B 排队共同改善或形成明确取舍 |
| 本地反压维持供给 | 触发、等待、排空时停止追加、恢复与近端缓存占用的完整链路 |
| 有限资源下可以运行 | 首包发现、状态占用、老化再发现、迟到反馈、等待与丢弃均可核算 |

对照应包含原生 DCQCN、无预测的网关控制、基于配置速率的预测以及相关在途量控制。工作负载、时间窗口、缓存、拓扑、预算来源和信息权限必须一致，不能依赖真实未来需求或服务制造优势。

评价还应报告完成比例、FCT、重传、残留字节、状态与反馈开销，以及域内流受到的影响。PFC 使用合并后的暂停时长和覆盖范围，不以刷新报文条数代替暂停程度。供给不足、服务骤降与恢复、反馈失效、多流启动和资源耗尽应作为边界条件考察。

若 B 队列下降但 A 等量积压、完成时间没有改善，结论只能是缓存位置改变。若误差改善很小或未知服务始终主导误差，也会削弱预测机制的研究价值。

## 13. 相关工作的启发

- **时延补偿与 Smith 类控制。** 可借鉴模型补偿和误差分析，但稳定性依赖具体假设，不能直接继承。[Mascolo，1999](https://c3lab.poliba.it/bibcite/reference/120)、[De Cicco 等，2011](https://www.sciencedirect.com/science/article/abs/pii/S0005109811001373)。
- **Bifrost。** 根据暂停历史构造虚拟到达，提示供给不足时推算量可能高于真实发送；在途感知本身已有研究基础。[Bifrost，§IV](https://cs.nju.edu.cn/tianchen/lunwen/2023/icnp23-peiwenyu.pdf)。
- **ATC。** 双端网关利用近端累计发送与远端转发反馈表达在途量，说明双网关和累计反馈本身不足以构成新贡献。[ATC，§IV-B](旧版本文件/参考方案/ToN2025--Re-Architecting_Traffic_Control_in_Cross-Datacenter_RDMA_Networks.pdf)。
- **HierCC。** 资源聚合与逐流分配可以并存，但预算获取依赖真实协议和观测条件。[HierCC](https://conferences.sigcomm.org/events/apnet2021/papers/apnet2021-3.pdf)。
- **BFC。** 动态队列和选择性反压有助于缓解队头阻塞，其效果依赖队列资源，不能直接归因于逐流整形。[BFC，§3.3](https://www.usenix.org/system/files/nsdi22-paper-goyal.pdf)。
- **Annulus 与 THEMIS。** 提示控制环协调及主动 CNP 的源 QP 信息要求。R5 保留原生 CNP 和既有 CE，需单独验证其耦合代价。[Annulus，§3.3](https://saeed.github.io/files/annulus-sigcomm20-cr.pdf)、[THEMIS，§IV](https://zhangmenghao.github.io/papers/ICNP2025-Themis.pdf)。
