# Proposed R2 实现与验证

依据 `docs/Proposed拥塞控制方案_R2_简化实用版_20260924.md`。
本次只保留 R2；按用户要求删除旧 Proposed、R1 控制实现及其入口。
其他算法和历史方案文档未改写。本说明记录可运行原型及其限制，不是性能验收报告。
下文的拓扑限制和数值结果记录的是此前的直连实验；多跳路径代码正在调整，
短时启动成功不能代替完整场景验证。

## 实现对应关系

| R2 要求 | 当前实现 |
|---|---|
| 接收端只观测和分配 | `Report()` 采 q、暂停时间、WAN/域内字节，计算 Ceff/x；F 独立使用正常容量与配置份额 |
| 只有一种周期反馈 | 序列化 STATE 从接收 Leaf 的优先级 0 经 Spine、DCI、真实 WAN 链路发送；无 ALARM、APPLY_STATUS 或确认协议 |
| 固定大小实际历史 | `ByteHistory` 存每箱 uint64 字节计数；发送事件写入，固定环形空间，不保留在线逐包列表 |
| 分箱重建 | `Reconstruct()` 从快照开始逐箱非负截断，保留 qhat/qpeak；不把闲置服务累积至后续突发 |
| 单一公式 | `Rate()` 从 V=max(0,Ceff-x) 扣除排空项，再取 F 和源端容量的上限 |
| 真正逐包执行 | 原 Qbb FIFO/MMU 配合出队资格判断；一个最大帧的桶，零速率清信用，恢复不赠送信用 |
| 简单近源 CNP | Qs 高/低水位滞回，逐流超额输入与最小间隔；原生反馈透传，最近有效反馈抑制近同时补发 |
| 简单有效性处理 | STARTUP/VALID/STALE/FALLBACK 是反馈有效性日志标签，没有拥塞/恢复状态机；短过龄保持目标，长过龄恢复静态上限 |
| 原生恢复和保护 | DCQCN、ECN、PFC 保持；不增加端侧提速、受控 ECN 托管或预测误差学习 |

源/接收组共用一个数据 PG。原有交换机 MMU 完成准入，真实数据保留在原 BEgressQueue 管理的组 FIFO 中，
没有额外无限缓存。源入队计数指已经通过准入的字节；MMU 丢包单独计入
`admission_drop_packets`，重传重新经过发送事件并计入真实历史。

流映射来自仿真登记，控制器只用身份、本地实际入队/出队、最近活动和反馈时间。
不会读取流未来大小或完成时间。活跃超时为 `max(2(df+db),2Tr)`，保留有本地排队或
WAN 出口暂停证据的流。这不是严格需求识别或逐流公平调度。

支持固定路由的多跳双 DC 拓扑：源主机→Leaf→Spine→源 DCI→WAN→接收 DCI→Spine→Leaf→接收主机。
按“源 WAN 出口方向、接收主机出口、PG”建立控制组；每组独立 FIFO/历史/STATE/目标。
观测点为接收 Leaf 的主机出口。源侧 CNP 经 Spine/Leaf 返回 RNIC。
同 PG 的域内数据和反向 ACK 计入外部竞争 x。每个方向按本地活动组执行有上限的最大最小
WAN 份额分配，作为公式中的 Csource；不读取未来流大小或完成时刻。不同组的整形资格
独立，物理 PG 的 PFC 和 MMU 仍共享，不增加总缓存。当前最多 120 个逻辑控制组。
不支持多网卡主机、多个源 WAN 的协同预算或运行中路径切换。ECMP 使用现有转发表和流散列。
固定组和 epoch 为 1；错误 group/epoch、旧序号、未来时间戳和已过龄快照被拒绝。

## 时间、分箱与反馈口径

在线历史按 WAN **实际发送起点**记账。固定 df 累加源 WAN 至观测 Leaf 沿途传播、每跳接收处理和最大
数据帧序列化时间；尾部短包的时延差属于离线校核的时间映射误差。dt/delay 转换使用
ns-3 的整数纳秒时间。组内取最大名义 df，metadata 同时记录最小值；中间排队不包含在
名义时延中，属于预测误差，不能把预计到达日志当真实逐包到达记录。目标更新在同一仿真时刻同步作用于出队资格，dg=0；更新前已经
开始序列化的包不能撤回，该包已经记入发送历史。

每次重建只查询 `[tr-df,t]`。已完成边界箱按重叠时长比例分配字节，当前未完成箱只
在已观测前缀中分配，不能用未来箱补齐。模拟开始之前明确为零；被环覆盖的历史则是
缺失，不能当零。每个 bin 递推后取 max(0,q)，qpeak 是箱边界峰值，会漏掉箱内峰值。

接收端无暂停时以已知容量作为服务估计；周期内暂停按不可用时间折算，采样时仍暂停
则 Ceff=0。空队列不会把 Ceff 降为实际低吞吐。F 始终是正常容量授权，暂停不会把它
重复减小；源端通过 V 和队列排空项选择 u。

STATE 使用实验私有 IP 协议号 249，共 114 B（80 B 状态＋34 B IP/模拟链路报头）。
核心字段为版本、group、epoch、seq、采样时间、q、Ceff、x、F。额外 8 B WAN_RATE
仅供固定速率外推消融使用，所有 R2 模式发送相同大小和频率的 STATE，使开销可比。
没有第二类控制包；原 CNP/PFC 仍使用现有格式。这不是商用协议/ICRC 兼容性证明。

`proposed-extrapolate` 在源侧执行接收测得的固定速率外推
`max(0,q+(WAN_RATE+x-Ceff)*(ta-tr))`，与同一线性模型在接收端外推再传递等价，
不使用源发送历史；这只是消融，不代表完整复现某篇论文或原 Proposed。

## 配置和入口

主程序六项 CLI 不变，`--cc=proposed` 表示 R2。配置中使用：

| 键 | 默认值/含义 |
|---|---|
| PROPOSED_OUTPUT | 控制日志路径；选择 proposed 且未设置时从 metadata 路径派生 |
| PROPOSED_PREDICTOR | 0 实际历史；1 旧快照；2 静态上限；3 接收测得速率外推 |
| PROPOSED_REPORT_PERIOD | 0.0002 s |
| PROPOSED_CONTROL_PERIOD | 0.00005 s |
| PROPOSED_BIN_WIDTH | 0.00005 s |
| PROPOSED_QREF | 0 表示由 Cnom×40 µs 推导；其他值为 B |
| PROPOSED_TAU | 0 表示 max(2(df+db),4Tr)；其他值为 s |
| PROPOSED_SOURCE_HIGH / LOW | 250000 / 62500 B |
| PROPOSED_UTILIZATION | 0.98 |
| PROPOSED_WAN_FRACTION | 1；混合流可设明确的固定 WAN 份额 |
| PROPOSED_EPSILON | 0.05 |
| PROPOSED_CNP_INTERVAL | 0.00005 s，不小于原有效通知量级 |

过龄门限为 db+3Tr+一帧链路阻塞裕量；再过 3Tr 回退静态上限。历史长度覆盖
maxAge+df+2Δ，并保留边界箱。1 ms、100 Gbps 接收出口检查中为 56 箱，即 448 B
字节数组，另有少量索引/容器状态。静态上限回退不保证未知拥塞下无损或稳定。

旧 `RESEARCH_*`、`R1_*`、`proposed-legacy`、`reactive-cnp`、`predictive-cnp`、
`r1-*` 入口已移除，不静默转换。旧配置需改用新键。PROPOSED_RECEIVER 已删除，接收组从登记流自动推导。默认 baselines 不设置观测输出时
完全跳过本模块；runner 为对照设置输出时只采样，不发送 STATE/CNP，不启用整形。

源队列和全网峰值/面积来自周期采样；接收峰值来自每个入出队事件。不能把采样峰值

## 之前直连原型的验证记录（2026-09-24）

已完成构建、Python 语法检查、diff 空白检查及以下检查，输出均放在 `/tmp`：

1. 早期 R2 数值检查：2.75 MB、45 Gbps，以及 F=30/V=50/排空10 Gbps
   时仍选30 Gbps、外部流量耗尽服务、逐箱空闲服务丢弃、部分箱、环覆盖、未来输入拒绝、
   零目标清除信用及恢复不补信用。
2. `/tmp/proposed-r2-0924-finite`：4×100 MB，WAN 200 Gbps、单向1 ms、接收100 Gbps，
   无发送窗口限制。四个 R2 模式和 DCQCN 均4/4完成。R2 最大FCT均53.990170 ms，
   DCQCN为62.288085 ms。实际历史版本逐包整形通过；四处数据字节均419200000 B；
   无准入丢包，源采样峰值3964584 B，接收事件峰值1048 B。
3. `/tmp/proposed-r2-0924-fault`：接收出口2 ms PFC，并在零服务阶段开始丢6 ms STATE，
   额外注入旧序号、旧epoch和未来时间戳。短过龄保持零、长过龄静态回退、新报告恢复均
   通过；4/4完成、无准入丢包、信用/字节检查通过。接收峰值8178592 B，最大预测低估
   8160776 B。说明周期反馈与长超时回退不能消除不可预见暂停的积压。
4. `/tmp/proposed-r2-0924-local`：4条WAN流加1条20 MB域内流，WAN份额0.75。
   5/5完成、无准入丢包、信用/守恒通过；WAN累计419200000 B，域内20960000 B，
   接收总计440160000 B。接收峰值878224 B。只验证分类/控制闭环，不代表公平性结论。
5. `/tmp/proposed-r2-0924-eight`：8×100 MB、接收50 Gbps、单向1 ms。R2和静态整形均
   8/8完成、最大FCT均186.858364 ms，R2逐包整形及已准入数据守恒通过；但出现1626次
   准入丢包，源采样峰值26654832 B。重传计入发送历史，累计WAN字节851942256 B。

第5项不能算无损缓存验收通过。日志明确报 ingress headroom 耗尽：已用55544 B、
上限56250 B、下一帧1048 B。现有公共 `ConfiguredHeadroomBytes()` 仅用
`link_rate×3×link_delay/8`，100 Gbps/1.5 µs 对应56250 B，未计配置的15 µs设备
接收处理延迟；这至少指出当前 headroom 规划不足的具体风险。本次没有增加共享缓存
或改动所有算法的公共 PFC 参数来隐藏失败，仍需单独校核完整 PFC 反应链的余量。

以上是实现检查。无竞争场景四个R2版本结果相同，尚未证明历史预测有独立系统收益；
不能将与DCQCN的差异全部归于预测。尚未完成文档中的时延/τ扫描、随机负载多种子、
尾FCT/混合流公平性和减流恢复归因等完整性能实验。

## 多跳、多接收组与双向验证（2026-09-24）

实际使用未修改的 `topology-longhaul.txt`（82 节点，WAN 200 Gbps、单向5 ms）。
以下 S0–S5 是功能回归：保留原文件的端点、PG、流数量，每条流最多10 MB，开始时刻
按 `0.01+(原时刻-0.01)×0.1` 缩短，停在0.12 s，无发送窗口限制。原正式流文件未改写。
S3 缩小后不再保留原来的长短比例，所以不是减流性能实验。

| 场景 | 组数 | 完成流 | 近源 CNP | 全网准入丢包 |
|---|---:|---:|---:|---:|
| S0 | 1 | 1/1 | 0 | 0 |
| S1 | 8 | 8/8 | 142 | 0 |
| S2 | 8 | 8/8 | 141 | 0 |
| S3 | 8 | 8/8 | 142 | 0 |
| S4 | 16 | 16/16 | 254 | 7921 |
| S5 | 8 | 12/12 | 206 | 0 |

每组均收到多跳 STATE、进入 VALID，结束时源和接收队列均排空；源 WAN 出队字节等于
接收组 WAN 入队字节。双向 ACK 已计入同 PG 的非受控流量。S4 的丢包发生在源侧准入，
不能用已准入字节守恒证明无损；其日志仍指向上文的 headroom 不足。没有为通过测试
修改公共 PFC 参数。完整原规模 S0–S5 的收敛/公平性/无损性能尚未验收。

故障测试改用同一分层拓扑、1 MB单流：Leaf 接收出口暂停4 ms，从21至30 ms丢 STATE；
检查零服务停发、短过龄保持零、长过龄回退、恢复，以及旧序号/epoch/未来时间戳拒绝。
单元测试另检查共享 PG 的逻辑组字节合计、某组无令牌时其他组可出队、PFC 同时暂停各组。
S0–S5逐包令牌重放与STATE返回时延下界检查均通过。测试在主机接收入口计数CNP，
再等待DCQCN减速计时器核对速率：S4的254个CNP全部到达，16个QP首次通知后均降速。
另在 `/tmp/proposed-multihop-ratio` 按原大小统一除以300复查S3/S5，保留长短比例，
分别8/8、12/12完成。4条WAN流加1条域内流的分层测试也5/5完成，WAN4192000 B、
域内1048000 B，准入丢包为0；DCQCN观测模式单流完成且未发送STATE/CNP。
100 MB暂停压力试跑曾因中间准入丢包未通过端到端线速字节守恒，因此使用1 MB隔离验证
反馈状态机；这不代表大流暂停压力已经通过。

输出位于 `/tmp/proposed-multihop-smoke` 和 `/tmp/proposed-multihop-fault`。
控制 CSV 新增 `group_id`，源份额为 `source_share_bps`；metadata 的 `groups` 保存两侧 DCI、
观测 Leaf、接收主机、PG、逻辑队列与各组时延。`.paths.csv` 记录实际 ECMP 路径。
分组分析必须按 group_id 处理；`network_queue_bytes` 和 `admission_drop_packets` 是全网值，
不能把不同组同一时刻的这两列相加。
