# Proposed R3 实现说明

`--cc=proposed` 对应 R3。本文说明实现，不声明性能提升或无丢包保证。

## 职责与数据路径

- `longhaul-convergence.cc` 创建 `DciGatewayNode : SwitchNode`，完成时通知源侧连接退出。
- `longhaul-r3.h` 从实际 ECMP 路径识别两端 DCI、B 向内出口，验证 ACK/CNP 回程经过 B。
  注册 IP、双方 UDP 端口、PG、流 ID、代次和固定路径时延；运行时不共享远端控制状态。
- `dci-gateway-node.{h,cc}` 保存本节点的 A/B 两种角色状态，管理需求、预算、预测及快照。
- `QbbNetDevice` 与 `BEgressQueue` 保存报文，按逻辑流队列执行令牌桶和可发送队列轮询。
  缓存准入、出队释放、ECN 和 PFC 仍经过 `SwitchNode`；逻辑队列映射回原物理 PG。

同一 DCI 在双向场景中同时具有 A/B 角色。组键为 B DCI、实际向内出口、PG。
不同主机可属于同组；没有主机直连 DCI 假设。

## 控制语义

B 每个反应窗口合并事件：`alpha=(1-gamma)*alpha+gamma*event`，有事件时
`r=max(probeRate,r*(1-alpha/2))`。使用窗口末更新，不按每个 CNP 连续降速。
恢复需要在至少 `max(recoveryPeriod,localFeedbackRtt)` 的观察区间内确有发送、近期仍有数据、
无新 CNP 且未暂停，然后执行有界加性增加。无数据不能自动增加速率。

B 在同一物理端口所有受控流间做等权、带上限的最大最小分配；暂停 PG 的上限为零。
端口总预算上限是 `utilization * portRate`，再扣除上个控制间隔中非受控报文的实际出队速率。
当前没有单独的每组管理限额，因此 `Fg=sum(bi)`。这不是精确预测其他业务的未来调度份额。
有积压时，服务预测只计有积压流的预算；无积压时用活动流预算估计能力，避免把无需求当零能力。
B 总受控队列超过共享缓存的 80% 时记录告警并使用保守预算，降至 50% 后退出。
该安全上限不执行 A 的队列排空公式。

A 周期向 B 报告活动/积压/关闭状态，B 同时保留近期到达的在途保护时间。
新流在首个预算到达前使用受端口约束的探测速率；A 的探测间隔取 `2*df+reportPeriod`，
B 取 `max(localFeedbackRtt,recoveryPeriod)`。速率不超过
`min(probeRate,(probeBytes-oneFrame)/interval)`，令牌桶突发为一帧，因此该区间探测量有界。
静默后 B 重新使用探测上限；令牌不随控制周期重新灌满。

A 按真实出队事件累加固定时间桶，从快照时刻减 `df` 推演至当前时间，等价于预测 B 的
`now+df` 积压，每个桶都做非负截断。边界桶按已观测部分均匀分摊，服务在快照间保持常值，
因此属于近似预测。公式为：

```
qhat_next = max(0, qhat + actual_sent_bytes - service * dt)
Ug = min(Fg, A_port_share, max(0, service - max(0, qhat-qref)/tau))
```

再以 `bi` 为逐流上限分配 `ui`。速率归零清除令牌信用；控制报文走优先级 0。
A 超过高水位后向有积压连接发限频近源 CNP，低水位后停止。
A 观察原始 CNP 仅更新抑制近源重复反馈的时间，不执行另一次乘法降速。

## 消息、映射与失效

协议号 249 携带 STATE/DEMAND，版本 3、epoch、序号、采样时间、组 ID、
队列/服务/预算/暂停状态及逐流 ID、代次、预算、活动/积压/关闭标志。
每帧最多 24 条记录，完整快照按序号缓存、收齐且校验后一次应用。
不完整或错误快照不替换已应用状态；乱序、错误代次、超龄、未知连接及重复记录被拒绝。
超时或历史不足时，不提高旧总限额，并限制在配置的保守端口比例以内。
周期控制消息继续发送，不受数据上限为零影响。

模拟器没有硬件双方 QPN 字段，使用显式注册的 IP/UDP/PG 双向映射。
独立 CNP 的 `fid` 是源 UDP 端口；ACK-CNP 还检查双方端口。
同一运行中拒绝复用/歧义 wire identity；连接关闭通过需求消息传递，状态保留到仿真结束，
不提前复用队列槽位，避免延迟反馈污染新连接。当前每出口最多注册 120 条受控流。

## 实现边界

- 固定路径、单对 DCI；不支持多源网关协调和运行中路由切换。
- 当前反馈包括 ACK/NACK 的 CNP 位和独立 CNP；没有隔离上游 ECN，称为路径拥塞反馈。
- 用 ns-3 同步时钟和固定路径的传播、接收处理、单帧序列化时间计算 `df`。
  未建模可变 WAN 路由/可变处理延迟；服务预测不能代表已知未来服务。
- RNIC 与网关仍是串联控制点。参数未标定，近源反馈、恢复和预测误差都需性能实验。
- 端口有限缓存/PFC 仍可能发生 admission drop，默认 headroom 沿用原实验，不能声称无丢包。
- 完整 R3 主路径之外，新增 `PROPOSED_RECONSTRUCT=0` 旧快照对照：只替换排空公式的队列值，保留有效性条件和其他控制。未保留 R2 静态/外推模式。

## 配置与验证

`PROPOSED_*` 参数见 `config-longhaul.txt`。时间为秒、字节为 byte，速率为 byte/s，
日志带 `_bps` 的速率字段转换为 bit/s。配置和完整命令由 runner 保存在每次运行目录。

```
./ns3 build longhaul-convergence longhaul-r3-test -j2
./ns3 run longhaul-r3-test --no-build
```

确定性回归覆盖带上限分配、无队首阻塞、PG 暂停、历史逐桶截断/过期、分片完整应用、
错误代次/乱序、积压流服务估计、重复 CNP 合并、源端不重复反应、无发送不恢复、PFC 服务归零和过期状态不增速。

实验验收必须另外核对预期 FCT 数、每条 flow 的有效 RX payload、网关 A TX/B RX 字节闭合、
队列与 MMU 记账、全网 admission drops，以及 B 降速和 A 预测是否实际触发。
`r3.summary.json` 提供全网停止时汇总；每个网关 CSV 的 `admission_drops` 只代表该网关。
缩小流量功能回归不能代替完整规模性能实验。

## 本轮验证记录（2026-09-29）

- 构建、`longhaul-r3-test` 和 runner Python 语法检查通过。
- 82 节点真实层次拓扑 S0–S5，每条流缩小为 1 MB，分别运行 DCQCN/R3；
  完成数依次为 1、8、8、8、16、12，逐流有效 RX payload 和网关 wire 字节闭合。
- R3 六个场景均有 B 降速；S1–S5 的最大预测积压约 3 MB，仅验证预测计算及 B 反应分支执行；历史样本的预测峰值发生在 A 队列排空后，不能据此证明预测限制了实际发送或带来收益。
  原始 CNP 在 A/B 的观察计数一致，A 没有执行重复乘法降速。
- 另测 120 条短流，最大组为 37 条，实际触发分片；120/120 完成，没有快照拒绝。
- 上述 R3 运行全网 admission drops 和停止时交换机剩余队列均为零。
- HPCC、TIMELY、Bifrost 的 S0 启动/完成回归通过，逐流 RX payload 闭合。

结果目录：`results/r3-validation-20260929-160143`，汇总见 `validation.json`。
这些是功能与一致性检查，不是完整 3 GB 场景的性能结果，也不证明其他负载下无丢包。

## 场景与公共测量更新

当前以 [README](README.md) 的实验用途、统计合同和模式命令为准。
`PROPOSED_RECONSTRUCT` 默认 1；0 使用有效快照队列，仍计算并记录重建值以便核对，
但不将重建值用于排空公式。相同历史有效性/超时检查仍生效。
网关 CSV 新增快照时刻/队列、预测终点、公式实际使用队列、组最终/端口分配前限额和暂停/有效性标志。
`longhaul-measurements.h` 为所有算法记录路径、供给结束、最终 RX、资源与队列。
历史 1 MB S2/S3/S5 仍只是功能记录，不是当前事件关系验收。
